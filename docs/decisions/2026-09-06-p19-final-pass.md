# P19 — the final pass: what the review found, what it missed, and what the build proves

2026-09-06, branch `feat/p19-final-pass`. The last coding session. What is left after this is
the phone, the piano and the five thresholds in `OWNER-GUIDE.md` §8, and none of those is a
prompt.

The review this acted on is `2026-09-06-once-over.md`. This note records three things it does
not: where the review was wrong, what a second hunt turned up, and what the verification
actually printed.

## 1. Where the review was wrong

Two of its findings did not survive contact with the code, and both are worth writing down
because the *fix* was still right.

**C3 — "the needs line ignores what the owner added" is unreachable.** The line is recomputed
at runtime now, and it should be. But `validate.py` refuses a build in which any rung is under
the floor, so `needs.songs` and `needs.exercises` are **0 on all 93 rungs** and the "this rung
wants one more song" branch never fires in a build that passed validation. The visible sentence
— "this rung has N option(s)" — was already counting the overlaid options. The staleness was
real and unreachable.

**C8 — the stray fixture is not a fixture.** `content/scores/pdmx/QmFixtureBachMinuet.mxl` was
to be moved under `tools/content/tests/fixtures/`. It is in no source table, copied by no build
step, and read by no test; and a byte comparison against the fixture archive's member of the
same name shows it is not that file either — it is the *converted* output of an early P13 run.
Moving dead weight into the fixtures directory would make it look load-bearing, so it is
deleted.

## 2. What the second hunt found

Nine species were named in the prompt. Seven produced something.

**A conditional rule implemented unconditionally.** Nothing new. (The review's own example was
fixed before this session.)

**A check that depends on something not guaranteed.** Three.

- The **ladder report described whichever build last wrote it** — its "wanted, and not bundled"
  section asked "has no file in *this* build" rather than "may not be shipped". One report is
  committed and both builds are checked against it, so the other always failed. This, not the
  six MuseTrainer ids, is the deeper half of C11.
- The **render manifest was keyed on the score file's sha256 alone**, so a new
  OpenSheetMusicDisplay left every remembered measurement valid and the check would report last
  month's numbers about this month's renderer, in silence. `--full` existed for exactly this and
  depended on somebody remembering to pass it. CI was protected by accident, because its cache
  key hashes `package-lock.json`; a laptop was not. The engraver's version is now in the key.
- **`validate.py`'s personal-build note counted a tag**, so a strict build announced it had
  bundled 159 items it had placeheld, and told the reader not to deploy the build that is for
  deploying.

**A control live before its dependency exists.** Nothing new.

**An allow-list that silently drops what is new.** Nothing new — but `coerceSettings` now has
the test that would have caught the last one, generated from `DEFAULT_SETTINGS` rather than a
hand list. Checked by deleting a line and watching it fail.

**A pattern narrower than the data.** One, and the largest finding of the session.
**`el()` did not understand `#id`.** It split its spec on `.` only, so
`el('input#folder-search')` created an element whose *tag name* was the whole string. The score
folder's search box, style select, two level boxes and rated checkbox were **not form controls
at all** — no `value`, no `checked`, nothing to type into, and `readFilters()` reading
`undefined` off each of them on every keystroke. It looked right because an unknown element with
a placeholder attribute renders as an empty inline box, and the screen had never been driven in
a browser. Five elements, one screen: the last one built, and the only one with no e2e.

**A number quoted from a biased sample.** Nothing new; the numbers in `00` and `01` were
re-measured instead (§4).

**A port that agrees in shape but not in detail.** Nothing new; the difficulty model's
cross-language test still covers what the two sides do.

**A document asserting behaviour the code does not have.** Twelve, all in the review's §2 table,
all corrected. The largest was `03` §3's seven-step pipeline, which is ten steps and puts the
render check in the wrong place.

**The same rule in two places, one of them wrong.** One, and it is the review's C2 with a third
place the review did not name: **Settings' track chips** answered "which tracks are on" a third
way, so on a fresh phone Plan showed six, Settings showed one and Today recommended from one.
`activeTracksFor` is the single rule now.

### Three more that fit no species on the list

- **The paper screen timed the click when it was scheduled, not when it is heard.** It converted
  the metronome's AudioContext times by hand rather than through `audio/clock.ts` — which the
  rhythm drill already used — so the device's **output latency was ignored**. On Android that is
  20–100 ms, and the screen's summary says "running 40 ms ahead of the beat" with a 10 ms
  threshold for "on the beat". The one number this screen exists to report was reporting the
  phone's audio stack. The anchor was also taken once at the start, so the two clocks' drift
  accumulated across a long practice.
- **The count-in used the length of the piece's first beat**, so a loop set after a tempo change
  was counted in at the opening tempo and then played at the section's. Six Chopin editions
  change tempo mid-piece, and looping a slow section of a fast piece is what loops are for.
- **A book piece kept its twin after the import was deleted**, so "With the score" stayed on the
  row and opened an "Unknown item" page.

### And one performance regression, worth its own paragraph

The PWA audit read **performance 77** — exactly the number P9 recorded *before* it made the
Score screen lazy ("entry bundle 1,576 kB → 227 kB, Lighthouse 77 → 98"). The entry chunk was
1,567 KiB again, with OSMD, VexFlow and smplr in it.

The cause was one line: `DrillScreen` gained a static `import { OsmdView }` for the drills that
show notation. **The drill route is not lazy and should not be** — Today's warm-up row is
usually a drill — so that import pulled the app's largest dependency back into the first paint.
Nothing noticed, because the audit is a command somebody runs by hand and P9's number lived in
a decision note.

Loading it inside `drawNotation` restores 1,567 KiB → 286 KiB and 77 → 95. An e2e now asserts
the entry chunk carries no engraver, by markers from inside the library rather than its name —
the name appears legitimately, as the destructuring of a dynamic import.

## 3. What the verification printed

Everything below was run on this machine at the end of the session.

**A full engrave of every file**, with the manifest deleted first, so nothing was remembered:

```
python tools/content/build.py --offline --strict-license --render --render-limit 0
1,256 items rendered fresh · 0 failed · 0 cursor/model step mismatches · 444.8 s
console: 9 items with OSMD's SkyBottomLine warning, 1 with a MusicSheetReadingException
content validation OK (1,533 catalog items)
```

**Both builds, both validations**, from one committed ladder report:

```
build.py --offline                       → validation OK, 1,533 items
build.py --offline --personal            → validation OK, 1,533 items
identical id sets; the only fields that differ are file, importHint, tags, source.checksum
```

**The three suites**: 499 Python, 1,398 unit, 259 e2e — the e2e run twice.

**The PWA audit**: all 18 PWA checks pass; performance 95, accessibility 100, best practices
100, SEO 100, agentic-browsing 100; precache 1,417 entries.

**Under a ×4 CPU throttle**: a 2-bar window renders in a median 36 ms, a pre-rendered swap in
4.2 ms, input to note-coloured in a mean 8.6 ms. The longest score in the library — Chopin's
Scherzo No. 2, 780 printed bars — puts its first window on the screen in 11.6 s.

**The folder at its real size**: a listing of 37,261 rows paints in 116 ms and searches in
36 ms.

## 5. Deviations

- **`--allow-nc` still appears in `docs/03` §1 and its source table**, against the prompt's
  "must not appear outside decision notes". `03` §1 is the licensing ledger and the flag exists;
  a pipeline document that cannot name its own flags is worse than one that does. What matters
  is that nothing *instructs* the owner to use it: `OWNER-GUIDE.md` and `README` say
  `--personal`, and `03` §1 says outright that `--personal` replaces it.
- **The shelf block collapses, but "I have this on paper" does not collapse with it.** The
  review asked for the section to disappear when there is no shelf; deleting that button with it
  would mean the shelf could never be started from the rung that wanted it, so it moves up
  beside the finder.
- **The stray fixture was deleted rather than moved** (§1).
