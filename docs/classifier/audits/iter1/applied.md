# Iteration 1: findings applied

One line per finding of `concepts.md` (every WRONG and UNSURE) and `completeness.md` (every proposed and widened
row, and the pedal correction), plus the 44 rule rows written this wave. Written by the applier, not a checker:
every change here is for iteration 2's checkers to verify. Generated by a script (the applier's worktree build/,
not committed) from the change data and re-checked against the yaml (every concept entry below equals the yaml's).

**The schema has no per-rung mapping.** `concepts.yaml` gives one `k`/`ch` per concept name. Where a finding
gives a different meaning per rung, the mapping holds the meaning the rungs that read items share, and the
per-rung meanings are in `amb` (listed in `generated/research.md` §7, where each rung rule must read them). A
per-rung field would need a `build_matrix.py` change, which this pass does not make.

**One instead rule added**: `written-part` (the learner works from a written part; items are written settings,
not lead sheets), for `arranging` and `twelve-bar-improv`, whose findings say the lead-sheet rule picks the wrong
items and no existing rule fits.
