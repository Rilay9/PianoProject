## 2. One-staff hand ruling — choose explicit catalogue truth, not an empty staff

**Choose candidate (b): carry the catalogue item's declared hand into model extraction for a one-staff item. Do not keep a silent treble staff merely to make OSMD number the sounding staff 2.**

CL15's important rule was that hand identity is **not inferred from clef or silence**. Passing an explicit `hands: left` fact from the admitted catalogue row does not violate that principle; it is exactly the explicit-truth alternative. The current model already keeps `note.staff` and `note.hand` as separate facts. A lone staff may truthfully remain `staff: 1` while its notes are `hand: 'L'` because the content object explicitly says this is a left-hand-only excerpt.

Keeping a silent treble staff would solve an internal numbering assumption by changing the learner's notation representation. That has the wrong dependency direction and knowingly risks an empty-staff rendering cost. The model should consume the content object's explicit role instead of forcing the score to impersonate a grand staff.

## 3. Required boundary for the app seam

Make the override narrow:

- Add an optional declared-hand input to the extraction/load path, sourced from the catalogue/content object where that value is authoritative.
- Apply it only to a **one-staff** model whose declaration is a single hand (`left` or `right`). Preserve the physical `staff` number from OSMD; override the semantic `hand` and therefore `handsPresent`.
- A one-staff right-hand item explicitly declared right remains right even in bass clef. A one-staff left-hand item declared left becomes left even though OSMD calls its staff 1. No clef inference.
- With no authoritative declaration, preserve today's CL15 behavior; do not guess.
- Do not use a `both` declaration to manufacture a missing second hand. A one-staff file declared both is a mismatch to report/validate, not two hands in the model.
- Two-staff scores keep the existing voice-home-staff / cross-staff logic. Catalogue metadata must not flatten a real two-staff score's per-note hand assignment.

This is a semantic input, not a new MusicXML parser rule.
