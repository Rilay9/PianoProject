# Reviewer response — U105b (Entry 192)

## Verdict

**APPROVE WITH ONE REQUIRED CHANGE**

The runner-red fix is correct for the no-run state: the refusal sentence is state/explanation text, not a density-critical label, and a fixed one-line clamp may not hide the actionable words merely because the runner's font is wider.

The newly discovered paused-run path exposes the same product invariant, though. The implementation may not keep the actionable refusal sentence cut merely because `PracticeEngine.running` stays true while the run is paused/held/demonstrating.

## Required change — a refusal remains whole even when the run object is still `running`

**Wrap the refusal there too.** The learner has just tapped a control and the app is explaining why that action did not happen. Hiding the control name behind an ellipsis is worse than allowing the header to grow temporarily, especially in the paused/held state where the score is not advancing.

The simplest implementation may be to remove the `:not([data-running='true'])` restriction from the refusal exception. The semantic rule is the important part: **whenever `data-sound-refused` is the reason the header is showing this sentence, the sentence must remain whole.**

Add a discriminating paused-run case under the wider-face/115% condition that proves:

- the refusal sentence is fully visible and not ellipsized;
- the already-drawn score keeps its frozen staff size while the temporary extra header line is present;
- the refusal does not overlap the active sheet/score controls;
- clearing/retrying the refusal restores the ordinary header height before successful continuation.

If simply allowing the extra line produces an actual overlap or unsafe stage geometry in that state, introduce an explicit paused/suspended refusal marker or another stable status surface. Do **not** solve the geometry problem by cutting the explanation again.

The existing mid-run one-line guard still applies to ordinary running status text. This exception is for the refusal state specifically; it does not globally un-clamp every line while a run exists.

Because the no-run condition should no longer be the product boundary, do not add a test whose purpose is to preserve that condition. Replace the surviving-mutant gap with the paused/refused discriminating case above.

This is the same learner-facing invariant already ruled in U105a/U105b, so it may return as a required-change fast path.
