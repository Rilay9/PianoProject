## 1. ACCEPT — G43 B-flat minor join

The fix is structurally sound.

`expand_fingering` now distinguishes:
- the first tonic,
- an interior tonic (`join`),
- the terminal tonic,

instead of assuming the one-octave starting finger is always the multi-octave join finger.

The exception is scoped in `SCALE_JOIN_RH`:

```py
("B-", "minor"): 4
```

rather than changing the right-hand join rule globally.

That is the right abstraction because the one-octave table is not itself wrong: Clementi and Kelley differ on the starting finger, while both support 4 at the interior B♭. The implementation preserves the existing Clementi start and changes only the sourced continuation fact.

The tests correctly distinguish:
- one-octave source truth,
- multi-octave join truth,
- generic mechanical guards.

The reported 624-staff diff showing only the four intended right-hand scale items changed is strong evidence against collateral mutation.

## 2. ACCEPT — G44 one seventh-spelling contract

`seventh_chord(root, quality)` is the correct repair.

The prior broken-seventh path rebuilt the same musical object from raw semitone offsets, duplicating the spelling mechanism and producing enharmonic nonsense. Both `make_broken_seventh` and `make_seventh_arpeggio` now consume the same quality-to-interval spelling truth.

That is exactly the architecture we want:

**one musical relationship → one spelling contract → multiple generated forms**

The representative sharp/flat/half-diminished/diminished tests and the cross-maker “same chord, same four names” test are appropriate. The semitone mutation proving both makers go red is especially useful.

## 3. ACCEPT — G47 seventh-arpeggio fingering provenance

The previous review required either a real source or no printed fingering.

The source now exists and matches the implementation.

Margaret Starr McLain, *Class Piano*, explicitly states that for seventh-chord arpeggios beginning on a white key, ascending LH is:

`5 4 3 2 1 4 3 2 1`

and ascending RH is:

`1 2 3 4 1 2 3 4 5`.

That is the exact sequence T53 already printed. The implementation's white-root condition therefore has an actual published basis rather than an inferred triad rule.

The source test over all 35 white-root seventh items, plus the mutation that passes generic guards but fails the source sequence, is the correct distinction between “physically plausible” and “this is the fingering the source gives.”

**G47 is closed.**

## 4. REQUIRED T53c — G48 G-sharp natural/melodic minor left hand

Do this **before D0**.

The finding is not merely a preference between accepted fingering schools. The current implementation applies the harmonic-minor left-hand table to natural and melodic minor forms, causing the thumb to land on F♯ in shipping G♯ natural-minor material and on the descending portion of G♯ melodic minor.

The mechanism is clear in `make_scale`:

```py
elif spec.mode == "melodic":
    fing = HARMONIC_MINOR_FINGERING.get(spec.tonic)
...
elif spec.mode == "natural":
    fing = HARMONIC_MINOR_FINGERING.get(spec.tonic)
```

For G♯ minor, that reuse is invalid because the harmonic raised seventh is F𝄪 (white) while the natural seventh is F♯ (black).

Kelley's chart independently supports a separate G♯/A♭ natural-minor LH pattern, `32132143`, rather than the harmonic/melodic `32143213` pattern. It also explicitly states the thumb should remain on white keys.

T53c should therefore model the real domain distinction:
- harmonic minor fingering,
- natural minor fingering,
- melodic minor ascending fingering,
- melodic minor descending fingering.

Do not patch only the five generated ids or add “if F-sharp then finger 2.”

Acceptance:
- G♯ natural minor uses the sourced natural-minor LH pattern;
- G♯ melodic minor may use distinct ascent/descent fingering where the source requires it;
- no thumb-on-black fault remains in the affected five items;
- a source-backed expected-pattern test exists;
- the current G48 pin is inverted/replaced rather than left as a tolerated known fault;
- diff proves unrelated scale families did not move unless their own source contract requires it.

That is the same semantic fault G47 just fixed.

Do not keep “printed but unverified” as a third state. Metadata uncertainty cannot make an engraved instruction non-authoritative to the learner.

Because this is a narrow one-family truth fix adjacent to T53b, doing it in T53c is cleaner than pushing it into D0's broader generator validity model.
