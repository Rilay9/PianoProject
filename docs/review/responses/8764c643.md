# Reviewer response — CL05a (Entry 194)

## Verdict

**APPROVE WITH ONE REQUIRED CHANGE**

The original CL05 required change is correctly built: hidden input no longer advances a Drill card, reaction timing excludes hidden wall time, and a live rhythm grid is re-anchored across the hidden span instead of silently catching up. The four implementation departures are justified and accepted.

The post-build questions expose one remaining learner-facing consequence of that fix, however: a rhythm card may become judgeable immediately on visibility return before the learner has an audible temporal reference, and may even judge against a click whose audio context has not resumed. That is not an acceptable resume contract.

## Required change — resume a rhythm card only after audible re-orientation

Use one rule for both questions:

**A rhythm card returning from a hidden span stays held until sound is actually available, then gives the learner one count-in before the held judged grid resumes.**

The count-in is not a new attempt and is not judged. When it finishes, continue from the same musical/judgement point the exact-span re-anchor preserved; do not restart the card from its beginning and do not skip hidden material.

This means:

1. Do **not** resume the judged grid immediately when `visibilityState` becomes visible. The proof case's next judged onset 300 ms after return is too abrupt to be a fair temporal reference after an interruption.
2. Do **not** judge against an inaudible click while `AudioContext` is still unavailable/suspended. The grid remains held until `audioEngine.ensureStarted()` has actually produced a running/usable context.
3. If the platform requires a user gesture before audio can resume, that gesture must be a **non-judged resume action**. Do not consume the learner's first musical answer tap as both “wake the audio system” and an answer against a grid they have not heard. If the existing Drill controls cannot provide such a gesture without inventing a new learner-facing control/state, stop and return that small UI choice instead of guessing.
4. Once audio is available, play the existing count-in policy, then resume the same held grid point and its click together. Hidden time remains excluded from every timing channel.

A discriminating case should cover at least: hide after the rhythm grid is established; return with the audio context still suspended; prove no judged-grid movement and no answer acceptance while sound is unavailable; resume audio; prove a count-in occurs before the next judged onset; then prove the grid continues from the pre-hide musical point rather than from bar 1 or from elapsed wall time.

X43 remains separate: the pre-existing missing count-in downbeat click is a general count-in defect, not created by this resume rule. Do not widen CL05a into fixing all count-in audio. X44 also remains separate as recorded.

## Four departures from the brief

**All four stand.**

- `excludeHidden(hiddenAtMs, visibleAtMs)` taking the actual span endpoints is more correct than a blind delta because a card can originate inside the hidden interval.
- Dictation must move the already-heard chord timestamps as well as the prompt because the answer duration is defined from those moments; moving only the prompt would manufacture timing.
- The pedal drill belongs in the same timing correction because its lift is measured from the chord event.
- `playPromptWithHelp` re-suspending on the shared flag is within the semantic boundary: a card that finishes opening after `pagehide` must not leak sound/input merely because the async setup completed late.

These are implementations of the already-approved “hidden is not practice” rule, not new drill semantics.

Once the audible-resume/count-in rule above is built and re-reviewed, CL05 may close.
