## Basis

I reviewed the immutable D3b handoff first, then the implementation and named evidence at the exact implementation commit. The shared mechanism is correct:

- `admittedForTeaching(item)` is the single exported reading of `unapprovedMusic(item) === undefined`.
- `eligibleFor` and `session.usable()` use that same predicate.
- The session card's `runs`, `done`, `measure`, fallback rung/prerequisite, exposure, and jam selections all pass through `usable()`.
- Keeping `Want.pool` unfiltered is necessary. Filtering it would erase an unmet ask and allow the card to advance to a later ask falsely; only `offer` is selectable.
- The committed catalogue probe changes 146 unapproved music rows on 59 cards to zero, with all affected rows replaced rather than silently claiming an unavailable ask was met. The path mutants restore the expected 44 warm-up, 50 review/rung, and 52 jam violations.
- The red-to-green consumer cases, six focused mutants, merged-checkout targeted run (105 passing), broader named run (276 passing), final named run (77 passing), Today browser run (16 passing), phone probe, TypeScript check, and app build support the mechanism. The two full-suite failures are the recorded untouched CRLF worktree cases, not D3b regressions.

This accepts D3b's session-card implementation. It does not accept the remaining learner-facing automatic selectors described below.

## Findings

### 1. Lesson-page automatic picks bypass the admission gate

**Classification: BLOCKS NEXT BRIEF**

At the exact implementation commit, `LessonScreen` still selects directly from rung lists for:

- **Start**, by taking the first playable exercise or song;
- **Climb the ladder**, by taking the first exercise matching the score target;
- **Quick check**, by taking the first exercise with a drill or file;
- the **duet** path, both an explicit `tool.item` and the implicit first playable song fallback.

These are learner-facing automatic offers inside D3a's “never teach wrong” contract. The handoff's catalogue reading that Start opens an unheard groove on eleven rungs is therefore a contract breach, not a display-only exception.

Required D3c change: apply the same exported `admittedForTeaching` predicate to every one of these picks. Each control must select the next otherwise-valid admitted option, or be hidden/disabled with truthful behavior when none exists. Do not add a second interpretation of the review fields.

Required verification:

1. null, `false`, and `true` teaching-use states at each selector;
2. non-music drills and notated items remain available where the existing contract admits them;
3. explicit duet `tool.item` and implicit song fallback are both covered;
4. a whole-catalogue rung-page sweep proves no automatic lesson-page control resolves to unapproved music;
5. a mutant that removes admission from each path fails for the expected path.

D3 is not closed until this fix-forward is reviewed. D4 must not rely on D3 being closed before then.

### 2. The two Latin asks must remain unmet pending an affirmative decision

**Classification: CONSTRAINS NEXT BRIEF**

For `latin.3` and `latin.6`, every current exercise candidate is refused by teaching-use admission. Leave those asks unmet. Rung placement, measured demand, or the need to fill a card is not approval.

A content owner may later add a genuinely valid alternative through its proper seam, but it must satisfy the ask and independently pass admission. Do not add or admit material merely as filler, and do not bypass the gate to preserve the row.

### 3. Some truthful replacements expose a ranking/content-order issue

**Classification: LATER WAVE**

After refusal, the jam/rung fallback can surface semantically thin replacements, including the transposition page at `chords-pop.7` and ear drill at `theory.8` under “Chords, form and feel.” D3b is correct to expose the next admitted option rather than conceal this. Treat G61 as a later session-composition/content-order problem; it does not justify weakening admission or blocking this seam.
