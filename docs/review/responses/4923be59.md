# Reviewer response — CL05 (Entry 187)

## Verdict

**APPROVE WITH ONE REQUIRED CHANGE**

The shared lifecycle mechanism is sound, and the five explicit judgement calls can stand. But the handoff's own follow-up list exposes one unfinished part of the seam's core invariant on Drill: while hidden, a rhythm card can still click/judge, reaction time can still include the hidden span, and hidden key/MIDI input can still reach a Drill card. Those are not later polish. CL05's approved contract is that hidden/background time is not practice and must not advance judged practice state or audio.

## The lead audio question

Do **not** generalise the Simon ruling into “every screen returns silent until the learner presses Play again.” Simon is a discrete prompt that was interrupted mid-cue; a partial prompt is not resumable continuity, so it correctly comes back silent and replays only on an explicit learner request.

The other three cases are continuous modes the learner explicitly left running. Their automatic resume therefore stands, provided they resume the same held activity rather than restart or skip it:

1. **Drill backing loop:** resume from the held bar/downbeat with the chart aligned. Do not restart the exercise from bar 1.
2. **Chord Chart and Lab:** resume from the held bar/downbeat with the existing count-in policy before sounding. The count-in is exactly what makes the return deliberate rather than an abrupt surprise.
3. **PDF timed/click mode:** re-arm the same page and its click; it is the continuation of the learner-started timed mode, not a new unsolicited prompt.

So judgement calls **1, 2 and 4 stand**. Call **3** also stands: a card whose between-attempt pause was interrupted waits for the learner rather than allowing the next prompt to start itself. Call **5** stands: Lab discards the cut bar/count-in material and continues only from the resumed window; hidden/cut material is never judged as if the learner played it.

## Required change — finish “hidden is not practice” for Drill

Treat the three Drill residues as one semantic required change, because they are three routes around the same already-approved boundary:

- A rhythm card must not keep its click/judged grid advancing while hidden. If simply stopping its clock would shift the scoring origin, suspend and re-anchor that origin on return so the same visible-time relationship is preserved. Do not leave the judged clock running merely because re-anchoring takes work.
- `meanReactionMs` must exclude the hidden span for the card that was interrupted. Hidden wall time is not learner reaction time.
- Key/MIDI events received while the Drill screen is hidden must not feed, score or advance a Drill card. The suspension boundary, not the individual drill kind, should own that refusal unless a card has a stronger existing rule.

Prove the boundary with a fake-clock/input case that hides a live rhythm card, advances a long hidden span and sends input while hidden: no sound/judged-grid progress, no answer progress, and no hidden duration in reaction/practice timing; after return, the card resumes from the same musical/judgement point rather than catching up.

This is a required-change fast path: it does not introduce a new product choice. If preserving the rhythm card's scoring origin requires a new state/ownership decision rather than a mechanical suspend/re-anchor, stop and bring that architecture choice back instead of approximating it.
