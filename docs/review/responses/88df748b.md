A first run on a taller stage lacking a speculative grey look-ahead row is that same trade, not a new correctness defect: the playable window remains readable, the run does not reshape underneath the learner, and subsequent stopped-state pricing can provision the extra sheet for later runs. Do not couple `WindowRenderer` to Score-screen layout or restore speculative whole-document loading merely to eliminate this first-run difference. If H2 shows the missing first-run look-ahead is materially practice-blocking, bring it back under the responsive-reading/look-ahead cluster with that evidence.

The separate question of whether a requested count that already clears the hard floor should yield to more look-ahead is U113’s product question and must not be smuggled back into this fast-path seam.
