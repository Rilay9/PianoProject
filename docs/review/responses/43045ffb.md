# Response to `43045ffb`

## Verdict

**APPROVE WITH ONE REQUIRED CHANGE**

X46 is now the right *kind* of lane: trace first, build only a small consumer/routing reconciliation if the current truths already support it, and stop with a measured gap rather than inventing an `Episode`, universal `Pass`, outcome enum or purpose ontology.

The required change is to the lane boundary before dispatch: **do not define “persisted/session-run fact” as synonymous with “CL11 evidence contract.”** Evidence ownership is about what observations count toward a skill/requirement/rung and how measured/unmeasured/unknown evidence is interpreted. A session item's purpose, opening intent, continuation intent or learner-facing outcome can be session/composer truth even if it is persisted. Route by semantic ownership, not by whether a field is stored.

R23's just-closed result makes this distinction concrete: a song-run session item can exist with no repository fact naming what application it is for. X46 should include that as a discriminating purpose case, but must not respond by adding a curriculum target field unless the trace actually proves one is needed.

### Required edit before dispatch

Replace the current boundary:

> a consumer change may be built here; an evidence-contract change includes what is written to storage or the run record and is CL11

with a semantic boundary:

- **Consumer/presentation/routing truth:** what a surface reads/says, which mode/tempo/continuation opens, and session-local purpose/intent/outcome needed to make the composed item coherent. These may belong to X46/session composition even if represented in persisted session state.
- **Evidence contract (CL11):** what observations/evidence are written as learning evidence, how evidence is interpreted, and what advances a requirement/skill/rung.
- **Missing domain truth:** if the trace needs a fact that belongs neither to presentation nor evidence — e.g. a stable authored application purpose — return the gap and identify the natural domain owner from the trace. Do not route it to CL11 merely because it would need persistence.

Do not broaden Outcome A into a large new session model. If a missing session fact would require substantial new architecture, report it and stop.

## 2. Fold R23's result into the purpose trace, not into a new schema task

R23 (`responses/f860c76e.md`) establishes a current, concrete case for points 1 and 2:

- 61 rungs require a song run;
- the repository currently names no claim/purpose that the song run is specifically applying;
- 41/61 name no detector-measurable claim at all;
- authored song order is current fallback behaviour, not proven pedagogical fit.

X46 should therefore add one narrow read-only question to its trace:

> When a composed item is a rung song-run, what fact currently tells the learner/session chooser **why this particular application is here and what it can count toward**? If no such fact exists, does the six-point contract actually require one for an honest learner story/chooser decision?

Possible outcomes are both acceptable:

- the existing rung/session reason already supplies enough purpose without a new target fact; say how, and R23's count-to-quality conversion remains parked;
- the contract genuinely needs a stable application purpose/target; report that missing semantic truth and what consumes it. Do **not** add the field in X46 unless the trace shows a genuinely small, natural existing owner and the change remains within the lane's small-build rule.

This is not a request to trace all 61 rungs or reopen R23's report.

## 3. Question 2 — consumer vs evidence boundary is right in spirit, but use semantic ownership

The intended separation from CL11 is correct, with the correction above.

Examples:

- Changing Today's stale wording, the completion action, or which mode/tempo opens is X46 consumer/routing work.
- Storing that an item was composed as **preparation** versus **criterion attempt**, if the trace proves the session needs that distinction, is not automatically CL11; it is session-item purpose truth.
- Changing whether a Wait-mode run counts toward a mastery requirement, how an unmeasured activity becomes evidence, or how `rungState` interprets observations is CL11.
- Changing a `sessionRun` field is not enough by itself to decide ownership; inspect what the field means.

This distinction matters because the exact failure we are trying to avoid is letting implementation location dictate the product model.

## 4. Question 3 — builder may choose, but the role of the item determines the honest answer

This does **not** require an owner decision before dispatch.

The builder should trace why the item was composed and choose the smallest honest learner flow:

- If the session item is presented as a **criterion attempt / evidence opportunity**, its opening state should be capable of satisfying that criterion. Opening in Wait at 70% when only Keep tempo at 80% can count is incoherent.
- If the item is deliberately **preparation**, it may open below/away from the criterion, but the learner must know that **before** playing, it must not wear pass/evidence language it cannot earn, and there must be a direct next route to the criterion attempt.

The design note should state which role the current composed item actually has and why the selected flow follows from that role. The landing review judges the evidence and learner flow; no arbitrary option should be chosen merely because both are technically possible.
