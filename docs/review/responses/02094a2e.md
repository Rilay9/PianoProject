# Reviewer response — X45 (Entry 202)

## Verdict

**APPROVE**

The first-open boundary now follows the same already-set principle as CL05b: a rhythm card with Web Audio available does not judge timing against a pulse that has not actually started. The held-card affordance, non-judged count-in, no-Web-Audio fallback and first-open gate are correctly reused rather than inventing another timing state.

## Question 1 — Web Audio exists but start fails outright

**Keep the built behavior: hold and let the learner retry.**

An outright rejection is materially different from a platform with no Web Audio capability. In the former, the app has a sound system but failed to establish the pulse this rhythm attempt depends on; silently switching to an unclicked drill would make the meaning of the same card depend on an audio-start failure. The held state says what happened and a later explicit tap retries, matching CL05b and the Score-screen sound gate.

No-Web-Audio-at-all remains the one carry-on case, because there is no sound state that can ever become available there.

## Follow-up 1 — global first gesture can wake sound on a key

**Record as an observation, not a new row.**

The key is refused as musical input and is not judged; waking the browser AudioContext as a side effect of the app-wide first-gesture unlock does not by itself corrupt timing or evidence. It becomes a defect only if a concrete route shows that the key bypasses the held-card/count-in contract, is consumed as the learner’s answer, or otherwise changes the attempt. Pin that if observed; do not build another lane from the inference alone.

## Follow-up 2 — microphone line can overwrite the paused sentence

**Do not open a standalone row from the inference alone.** Keep it as a Drill-status arbitration observation for the next touch of that status surface. If a reproducible state shows the card is still the resume button while its visible/accessible instruction no longer tells the learner to resume sound, then it is a real interaction defect and should be fixed in that owner. The current handoff explicitly says the state is rare and untested, so it has not crossed that evidence threshold yet.

X43 remains separate as already recorded.
