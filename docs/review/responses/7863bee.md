# G1 brief review — encounter model at 7863bee

**Verdict: APPROVE WITH ONE REQUIRED CHANGE**

The split is right. G1 should establish factual encounter history first, and G1b should build the intentional repertoire lifecycle over those facts. No current consumer needs a temporary lifecycle label, and `ProgressRow.status` remains outside both truths.

## Required change

- **BLOCKS NEXT BRIEF — make run-derived encounter history durable across session pruning, and define the run-derived kinds independently of evidence.** The brief says encounter history is durable and never pruned, while `attempted`, `practised`, and `performed` are derived only from `SessionRow`. The existing retention job can delete a run that has material but no evidence or `lessonId`; D4 already demonstrated that such a row may be the only proof that material was met. A separate non-run `encounters` store does not preserve played contact. G1b, G2, sight-reading novelty, and restored backups would then receive different history after the session cap is crossed.

  Revise the contract so every encounter fact used by `familiarity` survives retention. Choose and state one mechanism: retain the necessary session rows, or fold their material/passage/kind/time/source facts into a compact durable summary before deletion. If compacting, make the summary idempotent and avoid copying every live run into a parallel event log; `SessionRow` remains authoritative while present and the summary preserves only what pruning would otherwise erase. The backup must carry that durable representation.

  Define the facets by what happened:
  - every started/completed run is an **attempt** according to an explicit threshold already present in the run record;
  - an ordinary practice run is **practised** whether or not it produced usable evidence;
  - **performed** comes only from the run’s performance contract;
  - evidence presence, passing, and first-contact eligibility do not rename the encounter.

  Add a retention adversary: practise a passage, force the relevant session row through the real pruning path, then prove the material and covered passage remain attempted/practised, the other passage remains novel, D4 contact stays met with `how`, and backup/restore preserves the same answer. Include legacy unknown-material rows in the policy explicitly.

The G1 implementation should start from D4a’s landed tree because both change `ScoreScreen.ts` and the transfer record path. Keep D4a as its own reviewed seam.

## Accepted architecture

- **ACCEPT — factual history and lifecycle split.** Encounter facts and project intent have separate owners. Saving, learning, pausing, retiring, and returning belong to G1b and never manufacture view/hear/play facts.
- **ACCEPT — smallest live representation.** Non-run encounters belong in a small dedicated store; live runs remain the source for run details. A pruning summary, if chosen for the required change, should contain only the durable encounter projection.
- **ACCEPT — identity and passage scope.** D4’s identity is the right material key. Imports should acquire a hash of their stored bytes, duplicates should compare as the same material, and id-only fallback remains conservative. Passage coverage must normalize the session row’s played range and excerpt-local range into printed parent scope before inheritance is tested.
- **ACCEPT — one facts query.** Returning timestamps per facet, plus identity uncertainty, keeps policy out of the store. Composition-level hearing may be an additional facet, but it must not claim that another arrangement’s notation was viewed.
- **ACCEPT — first-contact derivation.** A generated phrase is first contact only if no prior run, hearing, or demonstration exists and no view occurred on an earlier visit. The same-visit view needed to read the phrase does not defeat the claim. Keeping `unseen` on the run preserves the exact fact the evidence reader used.
- **ACCEPT — extend contact without changing its verdicts.** Adding `how` while preserving D4’s `met | met-by-id | unmet` decisions is the correct compatibility boundary. Transfer selection can treat any prior view/hearing/play as contact while G2 later decides what kind matters for transfer evidence.
