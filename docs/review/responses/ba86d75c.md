## Verdict

**APPROVE**

The repair establishes the missing learner-facing ordering contract. On a tablet, `data-side` is now absent until the panel is genuinely decided, then becomes `text` or `empty` once for that screen; `WindowRenderer.create` sees that decision before pricing the first notation frame, except at the explicit bounded fallback. The late fallback preserves the panel column while undecided, so a late text panel does not narrow already-drawn music. Phone behavior remains immediate and panel-free.

Holding the panel elements in the screen closure is also correct. It closes the same per-opening lifecycle race exposed by this repair: an asynchronous lesson read belongs to the screen that initiated it, even if that screen has since been replaced. This should remain in U80 rather than be split into another row.

## Decisions

- **CONSTRAINS NEXT BRIEF — keep the wait bounded.** A score must not be withheld indefinitely by curriculum or lesson I/O. The current `Promise.race` shape is correct because it limits only the time after the score itself is ready, while the two panel reads began earlier in parallel.
- **LATER WAVE — U87 owns calibration of the 1,500 ms value.** `SIDE_PANEL_WAIT_MS` is a product-performance budget, not a new architectural truth. Keep it named and centralized. Change it only from observed first-load and throttled slow-tablet data that compares the two learner costs: time spent on “Loading…” versus a score drawn before prose arrives. The fallback mechanism is accepted now; the exact duration remains tunable.
- **CONSTRAINS NEXT BRIEF — preserve per-screen asynchronous ownership.** Do not return to document-wide id lookup for async panel completion. A late response may update only the detached screen and elements that requested it, never the currently mounted piece.
- **LATER WAVE — U86 may rename `empty` only atomically with the stylesheet.** The present word is correct because the full-width layout selector consumes it. A terminology cleanup must update the state writer, selector and tests together.
- **LATER WAVE — the remaining post-draw height change stays with U74's follow-up.** U80 fixes the panel-width race. It does not establish that the first notation frame has final stage height, and the captures still show the control-bar row changing that height.
- **PRUNE/MERGE — keep one panel-decision primitive.** All success, no-rung and read-failure exits should continue through `decideSidePanel`; do not add parallel booleans for readiness, visibility or rendering order.
