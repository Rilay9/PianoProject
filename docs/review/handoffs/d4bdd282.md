## Deviations from the brief, each with the line that forced it

1. **A fourth job, `e2e-coverage`.** The brief's own verification layer needs "the test-id coverage check's actual output on both runs" (Verification layers), and one of those runs has a red shard, which skips `render-and-validate` under its ordinary `needs`. Coverage therefore has to run as its own job, not as a step tucked inside render-and-validate.
2. **The shards restore `app/public/content` and install the content requirements**, beyond `app/dist`. Six specs read `public/content/*.json` from disk (first-day, offline, perf, placement-branches, side-panel-prose, sweeps), and two of them (placement-branches, side-panel-prose) build tests from the catalogue at collection time — without the content, the listing fails with ENOENT. `excerpts.spec` and `microscope.spec` separately run `tools/content/*.py`. Correction 2's own list ("the checkout supplies test/config/source files; the artifact supplies the exact built app bytes") did not anticipate either case.
3. **The content job builds with `npm run build`**, as the old `Build` step did, not `build:app`. The brief's own second-read item 3 requires both artifacts after the last content writer, and dropping the step would drop a check; the shards therefore serve the `npm run build` output, the same bytes the render check renders, where the old unsharded E2E served `build:app`'s build of the first content build. Inferred, not measured: a fetch that fails only in `prebuild` would now reach the browser tests too.
4. **`.gitignore` gains `app/blob-report/`.** The blob reporter (Decision 3c) writes there under any local `CI=1` run.
5. **No YAML loader parse of the edited workflow.** None exists on this machine: no Python `yaml` module, no `yaml`/`js-yaml` in `app/node_modules`, no Perl `YAML`, no `actionlint`; installing one was a download this lane did not take. In its place: `read_jobs` parsed every job, step and `with:`/`env:` key in the shapes the tests assert, `git apply --check` accepted both proof patches, and GitHub itself refuses an invalid workflow on the first proof push — so the first runner proof doubles as the YAML-validity proof this lane could not run locally.
6. **No Chromium cache added.** The brief's "the existing `actions/cache`" for Chromium does not exist in `ci.yml` today; each browser job runs today's install step (35 s and 29 s on the two proof runs), and OS dependencies install even on a cache hit.
7. **`test_ci_order.py`'s premise count was wrong.** The pre-T62 file held eleven tests, not the brief's assumed nine; `test_deploy_guard.py` imports its `read_steps`, so that function is kept rather than removed.
