**What the step does, what it can write, what it uses, and what its failure does.** After `npm run build` (working directory `app`, `PIANOPATH_STRICT_LICENSE=1`) has written the strict content build to `app/public/content` and vite's output to `app/dist`, with that content copied in, the step runs `python3 tools/content/deploy_guard.py --dir app/dist/content` from the repository root, on the 3.11 interpreter `setup-python` installed and the packages the earlier pip step installed. The script reads one file, `app/dist/content/catalog.json`; imports `validate` (and through it the pipeline modules the build step has already run); calls `validate.unfetched_placeholders(catalog)`; and prints to stdout. It writes nothing to `app/dist`, to a tracked file or to the content cache. The only files it can create are Python's bytecode caches under `tools/content/__pycache__`, which lie outside the uploaded `path: app/dist`. It makes no network call, reads no secret, and has no `env`, `with` or `working-directory`. The workflow's permissions (`contents: read`, `pages: write`, `id-token: write`) are unchanged, and the step uses none of them. On exit 0 it prints one line and the job goes on exactly as before. Exit 1 (a fetch placeholder, each id and reason printed), exit 2 (the catalogue is missing, is not JSON or is not a list) and any uncaught error (a traceback, exit 1) all fail the step. Nothing lets that failure through: there is no `continue-on-error` and no `if`, on the step or on the two steps after it. So `configure-pages` and `upload-pages-artifact` are skipped, the `build` job fails, `deploy` (`needs: build`) does not run, and the deployment already live stays live. The guard fails closed: a fault in the guard blocks a deploy the same way. It retries nothing. A push to the default branch and a manual dispatch are both guarded. The new `tools/content/*.py` file changes the content cache's `hashFiles` key once for `pages.yml` and `ci.yml`; `restore-keys: content-` restores the newest entry, as it does after any change to that folder, and the cache changes no output (docs/03 §3a).
