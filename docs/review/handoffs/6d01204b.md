**The mechanism.** The engine calls a tick a stall when it comes more than 25 ms after the one before. After a stall it held only the windows already over at that tick, for one tick interval from it. Under load the queue a stall builds is not drained by the next tick, so a window closed while a note stamped inside it was still queued, and the note then matched nothing. Three ways, each seen on the head (`timelines.md`):
- a second stalled tick closed a window the first stall had held, once that hold had run out (the first note judged wrong);
- a window that ended just after the stalled tick was closed at the next, unstalled tick, inside what should have been the hold (the second note judged wrong: the CI signature);
- the tick exactly one interval after the stalled one counts as no stall and no longer inside the hold, and closed a held window ahead of the queued note.

The fix: the hold is now one span, from a stalled tick to one tick interval after it, the bound inclusive; a stalled tick inside the span starts it again; the one-second stamp-trust limit still ends every hold. No timeout lengthened, no tolerance widened, the case unchanged.
