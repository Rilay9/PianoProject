## 1. U119: semantic minimum before the clip — CONFIRMED, with facts the ruling does not state

- **Where the group's width is decided.**
  - Sideways, the bar is one flex row that never wraps (`style.css`:965–979).
  - The group is `flex: 0 1 auto; min-width: 0; overflow-x: clip` (:982–1004, with the clip at :1003).
  - Every control is `flex: none` (:1016–1018), except the mode select: `#score-mode` (:3089–3100) outranks that rule by specificity and shrinks to 2.75rem.
  - So the group gets whatever the controls leave. Inside it, only the title shrinks (:1006–1013). Back, `bar n / m` and the status are `flex: none; white-space: nowrap` (:1023–1026).
  - They are clipped from the right in DOM order: Back, title, where, status (`ScoreScreen.ts`:1202).
- **`fitBarControls` cannot do option (c) today.**
  - It (`ScoreScreen.ts`:1481–1488) moves `OVERFLOW_ORDER` (Hands, then Hear it: :1591–1602) behind `⋯` only while `barIsOverfull` (:1460–1471) is true.
  - That function tests two things: whether the bar has more than one row (by rounded `top`), and whether ▶ or `⋯` is under 40 px.
  - Sideways, a squeezed group changes neither: the row cannot wrap, so the group shrinks and clips instead. Nothing moves Hands for the group's sake.
  - Option (c) therefore needs a new predicate.
- **The predicate is measurable as the code stands.**

  - The status comes after `bar n / m`, so cutting it never trips the predicate.
  - The predicate applies only where the group is drawn. Upright it is `display: none` (:2910–2916).
- **Fact for the brief: which text to price.**

## 2. U118: one-day bound and unit case (c) — CONFIRMED

- **No contract ends or rewrites a run after some span.**

  - Scope: `awaySeconds`/`awayFromMs` in `ScoreScreen.ts`, and the visibility handlers in `screenLifecycle.ts`, `sessionRunner.ts` and `boot.ts`.
  - `sessionRunner`'s "left from another day" (:240) belongs to the session record, not the Score run.
  - `AWAY_PRICED_S`'s comment (:270–273) names no mechanism.
- **The sentinel bounds the number of digits.**

  - The chip sets no `tabular-nums` (`style.css`:2393–2406), so digit widths can vary by font. A 16-digit run of the font's widest digit makes "widest" hold on any font.
  - `away` already takes `number | string`, so the sentinel needs no type change.

  - So that one call is the first observation. With `measuredWidth` at −1:
    - the width-change branch (:2669) is skipped;
    - `frozen` is never cleared (:2683);
    - `freezeAfterSettle` returns early, because `frozen` is still set (:3928).

- **What an honest version needs.**

  - Then change the width and call `observe()`. Right after that call, assert that `debugFit().frozen` is null: the size was released. It is taken again only after `FREEZE_SETTLE_MS` = 150 (:405).

## 3. T62: same-run state, previews, proof route, sharding

**(a) render_check.py's inputs — CONFIRMED; the ruling's list needs two more.**
- **What it reads and writes.**
  - `tools/content/render_check.py --apply` reads `<content>/catalog.json` (:247–249). `--content` defaults to `app/public/content` (`common.py`:49).
  - It passes `CONTENT_DIR` and `build/render-manifest.json` to the spec (:86–96; defaults at :219–221).
  - It writes durations back into that same file (:299–327, called at :259–260). It also fills a null `tempoBpm`, `timeSig` or `keySig`.
  - `validate.py` then reads `catalog.json`, `curriculum.json` and the score files under that directory (:2006, :2034–2048). It also reads `build/render-report.json` (:873, :900, :972), which the render step writes in the same job.
- **Generated inputs it consumes rather than regenerates:**
  1. `app/public/content/`: the catalogue, which is read and rewritten, and every score file, which the spec hashes from `CONTENT_DIR` (`content-render.spec.ts`:221–228, :259–263).
  2. `build/render-manifest.json`, which the spec reads and rewrites (:174–190).
  3. **The served app.**
     - The spec loads each score from the preview server at `/PianoProject/content/${item.file}` (:294). That is `app/dist`'s copy of the content, not `CONTENT_DIR`.
     - Today the web server rebuilds `dist` from the current `app/public/content` (`playwright.config.ts`, the `webServer` block, `build:app`). So the bytes hashed and the bytes rendered agree by construction.
     - With a "serve the existing dist" flag, they agree only if Job 1's `dist` was built after the last write to the content.
     - CI's `npm run build` step (ci.yml:184–186) rebuilds the content through `prebuild` (`app/package.json`). Both artifacts must therefore be taken after that step.
     - Either Job 3 keeps today's rebuild, or it checks that `dist/content` equals the restored `app/public/content`.
  4. `app/node_modules/opensheetmusicdisplay/package.json`: the spec keys the manifest on OSMD's version (:97–103). It comes from `npm ci`, not from an artifact.
- **Fact the ruling omits: when the manifest is saved for later runs.**
  - `actions/cache@v4` (ci.yml:61–67) saves in its post step, at the end of whichever job holds it, and only on an exact-key miss. Today that happens after the render check has added its entries.
  - Left in Job 1, a new key would save the manifest from before Job 3's renders, and later runs would render those files again.
  - The fix is to save after the render step (a restore/save split), keeping the key and paths that `pages.yml` and `render-full.yml` restore. The cost is time, not correctness.
- **Job 3 needs Python and `tools/content/requirements.txt`.** Without music21, `validate.py` skips two checks silently: at :886–889 it returns `None`, and at :1064–1067 it finds no faults.

**(d) Playwright config — CONFIRMED, with one caveat.**

  - The brief should state which attempt's trace is kept for a test that fails then passes on retry, which is U118a's race case.
