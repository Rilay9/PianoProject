# Correction to `path-forward-2026-09-30-addendum.md` — 2026-10-01

This correction supersedes only the addendum's statements that make `docs/prompts/convergence-2026-09-30.md` the live scheduler and its execution-precedence placement of that map. The rest of the addendum remains in force unless separately superseded.

## Replace the strategic-scheduler sentence in the introduction

The addendum currently says to “use the convergence map rather than the raw backlog.” Replace that execution meaning with:

> Use the **current product-convergence scheduler** (`docs/review/product-convergence-current.md`) and current-tree evidence rather than either the raw historical backlog or the September 30 convergence map. The September 30 map remains provenance for why rows existed and how they were grouped; it does not authorize current work by itself.

## Replace the live-scheduler paragraph in §1

The paragraph beginning “The first convergence pass has now happened” currently says `docs/prompts/convergence-2026-09-30.md` “is the current scheduler.” That sentence is superseded.

Current rule:

> The September 30 pass reconciled and clustered historical rows but did not complete product-level convergence. Its map is now historical planning evidence. `docs/review/product-convergence-current.md` is the live scheduler until a later current-tree product reconciliation replaces it. Before dispatching a surviving historical cluster, re-establish the current learner problem and solution shape from the current tree; do not inherit BUILD NOW / DECISION / READ / RE-CHECK as authorization.

The rolling-pipeline idea still stands: useful independent work need not stop while reconciliation proceeds. What changes is **what qualifies as useful independent work**. A stale cluster is not useful merely because a lane is free.

## Add to §3 / H2 interpretation

Final H2 remains the release-acceptance walk described by the addendum. It is no longer the first holistic product read. During development, a substantial learner-facing change gets the smallest representative whole-screen/whole-flow check that could reveal a wrong product shape when such a check can materially change the next decision. This is judgement, not a fixed cadence and not a duplicate final H2.

## Replace execution precedence in §11

For execution, use:

1. current owner decisions and explicit owner corrections;
2. latest explicit correction/supersession for the affected boundary;
3. `docs/review/product-convergence-current.md` for current scheduling/product-shape authority;
4. latest unsuperseded reviewer response owning the affected boundary;
5. current-tree reconciliation/disposition written after the September 30 synthesis;
6. `docs/prompts/convergence-2026-09-30.md` and the main path-forward documents for provenance/rationale only;
7. older wave plans/audit rows for older provenance only.

A historical row's priority or disposition never outranks a current finding that its problem is closed, its decision was superseded, or its proposed solution shape no longer serves the learner.

This correction is deliberately narrow. It does not turn `product-convergence-current.md` into a permanent sacred plan; that file is explicitly replaceable when current evidence changes the right direction.
