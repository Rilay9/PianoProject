> - the already-drawn score keeps its frozen staff size while the temporary extra header line is present;
> - the refusal does not overlap the active sheet/score controls;
> - clearing/retrying the refusal restores the ordinary header height before successful continuation.
>
> If simply allowing the extra line produces an actual overlap or unsafe stage geometry in that state, introduce an explicit paused/suspended refusal marker or another stable status surface. Do **not** solve the geometry problem by cutting the explanation again.
>
> The existing mid-run one-line guard still applies to ordinary running status text. This exception is for the refusal state specifically; it does not globally un-clamp every line while a run exists.
>
> Because the no-run condition should no longer be the product boundary, do not add a test whose purpose is to preserve that condition. Replace the surviving-mutant gap with the paused/refused discriminating case above.
>

## Hypothesis and its refuting test

**Hypothesis.** The `:not([data-running='true'])` clause on the rule at `style.css:6155` is the only thing standing between a paused/held/demonstrating refusal and the wrap U105b already gave the no-run state. Removing that clause alone reproduces, for the paused-run case, the same wrap already proved for the no-run case, without disturbing the mid-run guard the comment above it protects — because that guard only ever fires while the line shown is an *ordinary* running line, never the refusal sentence (`soundOffLine()` always wins the race in `drawWaitingFor`, premise 8).

**Refuting test, run before any edit (red first).** Reproduce the CI shape once more (the wider face or 115% text, the existing `WIDER_FACE` technique or the sibling convention), this time with `data-running='true'`: start a run, reach a paused/held/demonstrating state by one of the three paths above, refuse the sound the way the existing summary cases already do (suspend the `AudioContext` and hang `resume`), reveal the bar, and read `#score-waiting` through the same `read()` helper `score.screen.spec.ts:1474–1505` already has. If the sentence still cuts (`scrollWidth > clientWidth`, `textInside` false, `ellipsis` true) on the rule unchanged, the hypothesis holds and removing the `:not([data-running='true'])` clause is the fix. If instead the sentence is already uncut in this state on the committed rule, or removing the clause produces an actual overlap with the stage or score controls, or an unsafe stage-height jump mid-pause (`score.head-height.spec.ts`'s guard failing, or the drawn sheet overlapping the header), the "just drop the clause" hypothesis is refuted for the geometry reason the review names, and the paused/suspended refusal marker the review offers as the fallback is the fix instead.
