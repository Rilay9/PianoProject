## The goal, in the orchestrator's words

Nine tests in the converter's real-recording class — among them *no note is lost or invented between the file and the score* — and the parity test that holds the app's hand split to the Python converter's have never run in CI: the recordings they need are not in the repository, and the references CI can write hold no hand split. ## What is decided

1. **The cached fetch, verifiable from the published archive** (the reviewer's required change, `responses/f52ebde.md`). A step in `ci.yml` before "MIDI converter harness": restore `build/midi-real/` from `actions/cache` keyed by the archive's checksum; on a miss, download `maestro-v3.0.0-midi.zip` from the dataset's published location (https://magenta.withgoogle.com/datasets/maestro), verify its SHA256 against the publisher's figure for the MIDI-only v3.0.0 archive, `70470ee253295c8d2c71e6d9d4a815189e35c89624b76d22fce5a019d5dde12c`, before extracting anything, and extract exactly three members into `build/midi-real/` under the aliases `test_converter.py` expects — `bach-bwv885-prelude-2011.mid`, `grieg-op38-7-waltz-2014.mid`, `scarlatti-k525-2008.mid`. **The mapping is explicit and unique:** each alias names its archive member by path (the builder reads the archive's published metadata, `maestro-v3.0.0.csv`, to identify the one performance each alias means — the same three the main checkout's `SOURCE.md` names — and writes the member paths as constants in the step), or by a unique match against that metadata (composer, title, year); zero or several matches, and a missing or empty MIDI file, fail the step. `SOURCE.md` is written beside the files with the three member paths and their aliases, the dataset version, the archive checksum, the licence sentence quoted verbatim with its URL, the citation the dataset asks for (the paper and the version) and the date; the step's comment carries the same. **A cache hit is validated the same way:** the three files present and non-empty and `SOURCE.md` naming them, else the step fails — a restore is not proof the inputs exist. The archive itself is never committed and never uploaded as an app artefact; the cache holds the three files, not the zip; the licence permits sharing under its terms, and this project simply does not bundle or redistribute the recordings.
2. **The skip becomes a failure in CI.** `test_converter.py`'s class-level `skipUnless(have_real, real_reason)` stays for a developer's checkout, and in CI (`CI=1`, the convention Q24 set) an absent `build/midi-real/` is a failure naming the fetch step, like the other Q24 gates; `parity_reference.py`'s "skipped, missing" for a real file is a failure under CI the same way — its `return 0 if written else 1` would otherwise conceal a partial fetch (the reviewer's constraint): under `CI=1` any of the three real inputs missing exits non-zero naming the step, even when the committed-fixture references were written — so the three real references are written and `midiParity` holds the split on them.
3. **The two-hand fixture (Q46).** A committed one-track, two-hand MIDI under `tools/midi-cleanup/tests/fixtures/` written by a small script kept beside it (deterministic, its notes stated in the script), added to `parity_reference.py`'s `APP_FIXTURES`; the reference writer asserts a non-null `handSplit` for it, so *splits the hands the same way* runs (not skips) on every CI run, archive or not, and the entry shows the Vitest case's line running on the fixture.
4. **The path (Q46, P3).** `test_technique_units.py` resolves `build/catalog.generated.json` from the file's location, as the other content tests do, and skips-or-fails by Q24's rule from any working directory.
