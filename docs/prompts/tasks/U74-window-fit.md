## The goal, in the orchestrator's words

The Score screen draws the same two-bar scale two ways: opened by a link after a fresh load it fills two systems; opened from Today's card it sits in one small system at the top with the rest of the stage empty. That is the first of the three goods lost on the path every learner takes. The likeliest mechanism, to be tested first and not assumed: on in-app navigation the renderer is created while the stage's size is not yet what it will be (the header, the status line and the bar settle after), so the window's scale is fitted to a wrong height and nothing refits it; a fresh load measures the settled stage. After U74 the renderer owns its stage's size — it measures the stage when the layout has settled and refits whenever the stage changes by more than `worthRefitting` allows — so both paths draw the same, held by a test that opens the same item both ways and compares the system count and the staff height; and the window rule's choice for a short item on a wide stage (E30) is judged on the whole gallery and the corpus, changed only if every size looks better.
