## What is decided

1. **Q64, the evidence manifest.** `tools/docs/evidence_manifest.py <seam>` reads a seam's capture folder (`docs/prompts/runs/<seam>/`) and the worktree's git state and writes `docs/prompts/runs/<seam>/MANIFEST.md`: for every capture its command (the first line of the capture, the convention every builder has followed), its exit code (the last line), its size and sha256; the seam's changed files by path with their blob shas; the red lines and mutants listed; the chain's exit file; the CI run id and conclusion for the push that carried the seam where `gh` can read it, else "not yet run". The manifest is data, never prose: no judgement, no summary. A builder runs it last; the orchestrator's record step runs it again on the merged tree and commits it. Tests on a fixture capture folder: every field, a missing exit line refused, a capture without a command line named.
2. **Q65, the path-to-checks map.** `tools/docs/checks_for_paths.py <path>...` reads a committed map, `docs/prompts/checks.json` — each entry a path pattern and the minimum checks a change under it requires (the content build, the validator, named content suites, typecheck, lint, named unit files, named specs, the record check), derived first from `docs/08`'s file lines and the last five landings' chains — and prints the union of checks for the paths given, in the chain's order, as commands; the orchestrator's chain for a landing is that output, and CI's steps are asserted to be a superset by `test_ci_order.py` (a new case). Tests: a fixture map; a path under no pattern names the fallback (the full suites); the union deduplicated and ordered. The map itself is the sweep's deliverable, reviewed by the reviewer as data: one line per pattern with the reason.
3. **The record's recurring faults.** (a) `split_prompt_views.py` runs inside the content build (`build.py`'s last step) so the views cannot be stale on a built tree, and `test_prompt_views` stays as the gate; (b) a helper for the record scripts' matrix edits (`tools/docs/matrix_edit.py`: edit a row by id, add a row after an id, both re-searching after each change and refusing a silent no-op) with tests, so a stale replace is impossible.
4. **Q63 recorded beside the workflow:** the rule (docs-only pushes neither start nor cancel a run; a code push cancels the run in progress) in `docs/08`'s CI paragraph and in `.github/workflows/ci.yml`'s comment — the workflow's comment is already there; `docs/08`'s text goes in the entry's doc rows (E2a holds the file).
5. **Not this sweep's:** any change to what a test asserts; the checks' content (what a path needs is read from `docs/08` and the chains, decided by the reviewer as data); the CI workflow's steps (Q47's file; only `test_ci_order.py`'s new case reads them).
