## Hypothesis and its refuting test

**Hypothesis:** at the canonical sizes, there exists at least one piece × bar-count cell where the requested count already clears the hard floor by a real margin, yet a smaller count (also clearing the floor) would give strictly more look-ahead — the concrete shape premise 1's "comfortable threshold" question is about. **Refuting test:** build the table (item 1 below) across the full grid (4 pieces × Bars 4/6/8 × 2 sizes = 24 cells) and check, for every cell, whether the `barsAsked − 1` candidate already sitting in that same cell's pricing pass (`debugFit().priced.candidates`, `barsAsked` held fixed exactly as item 1's counterfactual reads it) shows a larger `systemsPerWindow` than the asked candidate's own, or — wherever item 1's accessor question is answered and a per-candidate look-ahead flag exists to read — a look-ahead row the asked candidate lacks. If no cell shows either kind of change, the hypothesis is refuted for this corpus at these sizes, and the report says so plainly — the question would then be real in the abstract (the contract has no rule for it) but not yet demonstrated in practice, which is itself the honest finding to hand the reviewer and owner, not a reason to manufacture an example.

**A second, narrower hypothesis** (premise 5): U32a's own Nocturne-at-Bars-8 picture is fully explained by the existing hard floor alone. **Its refuting test:** read `staffPx` for `shown = 8` directly from that cell's `debugFit().priced.candidates` entry where `shown === 8` (`WindowRenderer.ts`:2033–2039 — the same fixed-`barsAsked` pass item 1's counterfactual reads, not inferred from the UI sentence) and confirm it is under 22 — if it is, premise 5's reading holds and that specific picture is not evidence for this brief's open question (it is U32a's own, already-settled territory); if `staffPx` at `shown = 8` is in fact at or above 22, the hypothesis in the paragraph above gets a concrete instance and the report says so.
