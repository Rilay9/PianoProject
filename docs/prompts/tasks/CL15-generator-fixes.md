## Premises at the lines (HEAD 00586f97)

1. **G51 — the tremolo "in thirds" is always a major third.** `family_contracts.json`:2679–2682 names the fault in its own words: `"name": "an octave tremolo, or a major-third tremolo moved by step"`. `generate_exercises.py`:2568–2572, the `TREMOLOS` table: `"third": (4, 1, 3, 5.0)` — always 4 semitones. :2591–2592, `make_tremolo_octaves`: `roots = scale_obj.getPitches(...)[:4]` (the tonic major scale's first four degrees); :2602, `high = up(low, semitones)` for every root. :3611–3619, `up()`: `p.transpose(interval.Interval(SEMITONE_INTERVAL[semitones]))`, spelled as the named interval every time — always a major third for `semitones=4`, whatever scale degree `low` is. In C major that gives C–E (correctly major) but also D–F♯ and A–C♯ (should be D–F, minor thirds, diatonically) — the fault as named.
2. **G51 — the sixteenth-syncopation item's title and tags overclaim what its own contract disowns.** `family_contracts.json`:1742–1759: the `tied-across-bar` variant's `target.primary` is `tie` (correct — no syncopation claimed); the `sixteenth` variant's target is `notJudged: {candidate: "rhythm.sixteenth-syncopation", why: "the sixteenth variant's off-beat notes are eighths, and the app's syncopation (T37's definition) counts a note of a quarter or longer off the beat: the detectors find no syncopation in it..."}` — the contract is already honest. `generate_exercises.py`:2910–2911 gives the sixteenth variant's title as `"Sixteenth-note syncopation"`, and :2938–2941's `catalog_entry` call tags every syncopation-family item, both variants, `["rhythm", "syncopation", variant]` — the title and the tag both claim the one thing the contract next to them says the detectors cannot find.
3. **G51 — the pentatonic items are under the five-second floor and the check that would catch it cannot see a duration.** `generate_exercises.py`:5612–5652, `make_pentatonic`: `bpm: int = 72` (default, never overridden at the call site); for `form == "pentatonic"`, `up_` holds 5 degrees plus the octave (6 pitches), `seq = up_ + reversed(up_)[1:]` (11 notes), `add_notes(rh, seq, fingers, 0.5)` — 11 eighth notes, 5.5 quarters, ≈4.6 s at 72 bpm (the `"blues"` form's 6 degrees give 13 notes, ≈5.4 s — already over the floor, unaffected). :6264–6268, the only call site: `for k in (["A"] if quick else ["A", "E", "D"]): for form in BLUES_SCALE_FORMS: items.append(make_pentatonic(k, form))` — bpm is never passed, so every root of the `"pentatonic"` form is the same ≈4.6 s. `tools/content/render_check.py`:267–296, `implausible_durations`: a measured duration outside `MIN_DURATION_SEC`–`MAX_DURATION_SEC` is reported and the report says it explicitly, :294, "not written to the catalog"; :299–320, `apply_durations`, :319: `if duration is not None and MIN_DURATION_SEC <= duration <= MAX_DURATION_SEC: entry["durationSec"] = duration` — an out-of-range duration is simply never assigned, so `durationSec` stays absent. `tools/content/validate.py`:354–357: `duration = item.get("durationSec"); if duration is not None and not (MIN <= duration <= MAX): ...` — the floor check only runs when a duration was written, so an under-floor item whose duration was withheld for exactly that reason clears the check by never being measured at all.
4. **G54 — power_chord's canonical root is never generated.** `family_contracts.json`:4172–4182, `roles.assign`: `{"role": "canonical", "when": {"key": "C"}}`. `generate_exercises.py`:6240–6241: `for k in (["A"] if quick else ["A", "E", "D"]): items.append(make_power_chord(k))` — C is never a key in this loop, in `quick` mode or the full plan. The maker's own comment, :6232–6234: "The keys are the ones the track is played in rather than all twelve... a power chord in G flat minor is not breadth" — the A/E/D choice is deliberate and already reasoned; C was never meant to ship.
5. **G7 — every melody is forced to start on D or E, never the tonic.** `generate_exercises.py`:1968–1999, `make_interval_reading`: `degree = 1` is seeded once, before the loop, as a bookkeeping value standing in for "the previous note" — it is never itself written. The first iteration computes `move = rng.choice([-2, -1, 1, 2])` (0 is not a choice) then `candidate = degree + move`; out of range, it bounces: `candidate = degree - move`. Working through all four values of `move` (−2 → bounce to 3; −1 → bounce to 2; 1 → stays 2; 2 → stays 3) shows the first written degree is always 2 or 3 (D or E in the fixed C position) and can never be 1, 4 or 5. :2007–2010, the fingering line (`if index == 0: n.articulations.append(Fingering(deg if hands == "right" else 6 - deg))`) already reads whatever degree the first note lands on, so it needs no change once the bias is removed.

'L' : 'R';` — hand is derived purely from staff index, never from clef. `app/src/engine/sightReading.ts`:2981, `const staves: 1 | 2 = options.leftHand === 'none' ? 1 : 2;` is the one place the app already writes a genuinely one-staff piano piece, and there a single staff means **no left hand** — the opposite of what U68 needs. So a bare single bass-clef staff, numbered the way every single-staff part is, would read internally as the right hand's part. This is a hypothesis, not yet tested (see below), because I did not run code to confirm it — read-only work here, no build or test. The ruling forecloses one path before the probe even runs: whatever it finds, the fix is never a rule that reads bass clef as left hand — hand identity stays independent of clef, staff silence or "only staff present" (`docs/review/responses/questions-e71ef3ad.md` §CL15).

## What to build

1. **G51 — the tremolo in thirds is spelled diatonically.** Truth: a "third" tremolo, walking up the tonic's major scale, plays the scale's actual third at each degree (major where the key gives a major third, minor where it gives a minor third), the way `make_interval_reading` and `make_pentatonic` already compute degrees with `scale_pitches` rather than a fixed semitone count. Mechanism: for `shape == "third"`, replace `high = up(low, semitones)` with a diatonic third above `low`, computed from the tonic's key (not a bare semitone count); the `"octave"` shape is untouched (an octave is an octave at every degree). Contract: `family_contracts.json`:2682's `"name"` text corrected to say what the fixed maker now does; version 1 → 2 for the `"third"` shape's items only (`"octave"` items keep version 1 — their music does not change); `identity_pins.json` rewritten for the changed items.
2. **G51 — the syncopation family's title and tags stop claiming syncopation where its own contract disclaims it.** Truth: an item's title and tags never assert the one thing its own contract's `notJudged` entry says the detectors cannot find. Mechanism: the sixteenth variant's title changes from "Sixteenth-note syncopation" to a name that states what it is (a sixteenth-note rhythm reading drill, the contract's own `"name"` field already says roughly this: "a tie across the bar line, and a sixteenth-note figure, over held chords"); `catalog_entry`'s tags drop the bare `"syncopation"` tag for the `sixteenth` variant (the `tied-across-bar` variant keeps it only if its own target still names it — it does not, its target is `tie` — so both variants' tags lose the bare claim; a `rhythm` and a `variant`-named tag remain). No notes change; no version bump.
3. **G51 — the pentatonic items clear the five-second floor.** Truth: every `"pentatonic"`-form item's written duration is at least 5 seconds, measured the same way `render_check.py` measures it. Mechanism: for `form == "pentatonic"` only, play the ascend-and-descend figure twice rather than once (`seq = seq + seq`), the same fix `make_broken_seventh` already uses for the same reason (:1753–1761, "the figure repeats rather than slowing down"); the `"blues"` form is untouched (already over the floor). Version 1 → 2 for the `"pentatonic"`-form items; the `"blues"`-form items' pins are unchanged.
4. **G54 — power_chord's canonical role names a root the plan actually ships.** Truth: the family's canonical item is one of the items the plan generates. Mechanism: `family_contracts.json`:4172–4182's `roles.assign` canonical `"when"` clause changes from `{"key": "C"}` to `{"key": "A"}` (the root `quick` mode alone generates, and the first of the three); a new contract test (`test_family_contracts.py`) asserts, for every family whose `roles.assign` names a canonical `"when"` clause, that at least one item in `tests/planned.py`'s built plan for that family matches it — general over every family, not power_chord-specific, so it also proves the other 48 canonical-by-key families are not silently wrong the same way. Mechanism: seed the first event directly (`rng.choice([1, 2, 3, 4, 5])`, written like any other event) rather than deriving it from a phantom "previous note" at `degree = 1`; the rest of the walk (`move`, the edge bounce, the tonic ending, the approach note) is unchanged. Version 1 → 2 (the notes of some seeds change); `identity_pins.json` rewritten.
6. **U68 — a genuinely left-hand-only item is written on one staff, not a silenced two.** Step 0, the probe (run first, before any generator change): a small fixture — a hand-written single-staff, bass-clef MusicXML string, four bars, no second staff — read through `extractScoreModelFromSheet` in a new Vitest case; assert whether its notes carry `hand: 'L'` or `hand: 'R'`.
