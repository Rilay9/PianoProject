## Hypothesis and its refuting test

**The shared hypothesis.** Every non-Score practice surface reads an unconditional wall-clock or `performance.now()` source for its own progression and duration, never checking `document.visibilityState`, so a background span is either silently absorbed into elapsed time (Drill's chorus, Drill's four duration sites, Drill's dictation ticker) or left running audibly (Simon's `setTimeout` chain, the Chord Chart and Lab metronomes/kits, Lab's `playCall`). Refuted for the whole cluster if any of the four already special-cased hidden state — premise 2's grep found none.

Per screen:
1. **Drill's chorus/bar readout.** Refuted if `formPosition`/`formStartedAtMs` already corrects for hidden time; premise 7 shows `stopFormTicker` only fires on dispose or finish, never on hide — unrefuted.
2. **Drill's Simon sound.** Refuted if the scheduled `playbackTimers` are already cleared somewhere on hide; a search of `playbackTimers` usage outside the drill's own reset/dispose paths finds nothing — unrefuted, and stated as a targeted rather than exhaustive search of that one identifier.
3. **PDF's auto-advance.** Refuted if `arm()` already reads `document.visibilityState`; premise 10 shows it does not — unrefuted.
4. **Chord Chart's audio and counter.** Refuted if `Metronome`/`DrumKit` suspend themselves on hidden; premise 13's scoped search of `app/src/audio` found no such code — unrefuted.
5. **Lab's trade clock and call sound.** Refuted if `judgeTrade`/`reportTrade` already exclude hidden time from the judged window (`LabScreen.ts`:609–632 measures the window by wall/audio clock with no visibility term) — unrefuted at HEAD.

## What is decided

**Buildable now (entailed by Part 19/20 §4 and the premises above, no product choice left):**
- A new export in `screenLifecycle.ts` gives each of the four screens two things: (a) a suspend/resume subscription keyed off `visibilitychange` (and `pagehide`, matching `sessionRunner.ts`'s own belt-and-suspenders pattern at :219) that calls the screen's own existing stop function on hide and a resume function on show; (b) an active-time-only elapsed-ms reader, parallel in shape to `sessionRunner.ts:188–230` but a new, separate primitive (see *Decided by the orchestrator*), for Drill's four duration sites.
- Wiring: Drill stops `formTimer` and `dictationTimer` and cancels pending `playbackTimers` and `feedbackTimer` on hide (the second read of the responses at `e71ef3ad`: `feedbackTimer` → `endFeedback` → `advance` → `playPromptWithHelp`, `DrillScreen.ts`:1450–1452, :1358–1363, :1268–1300, is a second, independent path to sound the hide handler must also close, or a feedback pause that elapses while hidden auto-plays the next prompt); the form and dictation tickers resume fresh (not "caught up") on show, while a Simon prompt cut off by hiding stays silent on show until the learner asks for it again (the next bullet); Drill's duration reporting switches from `Date.now() - startedAtMs` to the active-time reader. PDF calls its existing `disarm()` on hide and `arm()` on show (`arm()` already re-derives its interval from the current `index`, so resuming is a re-arm, not a rewind). Chord Chart and Lab must stop the metronome/kit/piano on hide and resume the *audio* without rerunning `start()`'s/`startJam()`'s reset of `bar`, `chorus` and `tradeIndex` — a new resume path, not a call to the existing reset-bearing `start()`.
- **The Simon chain's interrupted prompt** is now ruled (`responses/questions-e71ef3ad.md` §CL05): *"return visible silently and require the learner to ask to hear the prompt again; when they do, replay it from the start"* — never auto-replay sound merely because visibility returned, and *"do not score the interrupted prompt as an attempt."* Touches `cueSimonTurn` and `showChainOnKeys` (`DrillScreen.ts`:1008–1064): the hide handler cancels `playbackTimers`, exactly as `clearPlayback` already does for a skip or a manual replay (:695) — but, per the second read of the responses at `e71ef3ad`, it must not also zero `simonAnswerFromMs` the way `clearPlayback` does. Zero opens the answer gate (`onNote`, :652: `if (drill.kind === 'simon' && performance.now() < simonAnswerFromMs) return;` — zero makes that comparison false, so a key press is fed to scoring), and a key pressed after the screen returns, before the learner asks for the replay, would score the interrupted prompt against the ruling. The gate must instead stay shut on hide — held past whatever `performance.now()` can reach until the replay's own `cueSimonTurn` (:1016) reopens it with the new prompt's timing — and the hide handler must not call `advance()` either: `SimonDrill.next()` (`engine/drills/simon.ts`:524–536) scores an unanswered `current` prompt as a broken chain the moment `next()` runs, so the interrupted prompt stays `current`, unadvanced and unscored, until the learner actually answers it. `feedbackTimer` → `endFeedback` → `advance` → `playPromptWithHelp` (see the wiring bullet) is a second, independent path that starts sound without a request; a pending `feedbackTimer` must also be cancelled on hide. While the chain is held silent, the status line must not keep saying `SIMON_LISTENING` ("Listen — the app is playing.", :163, set at :1011): with the timer that would switch it to `SIMON_YOUR_TURN` (:1017–1022) cancelled along with the rest, that line is left stating something no longer true, so the hide handler sets a truthful line that says the prompt was interrupted and points at `▶ Play again`. The ask-again control the ruling requires already exists: `▶ Play again` (`drill-replay`, :2258–2264) calls `playPromptWithHelp(current)`, whose `playPrompt` already clears the old timers (`clearPlayback`, :752) and re-walks `target.playback` from `atMs: 0` (:773–779) — already a replay from the start, so hiding needs no new control, only a handler that stops the chain re-sounding on its own the moment the screen shows again.
- None of this touches `ScoreScreen.ts`, `sessionRunner.ts` or `sessionRun.ts`. A learner meets, concretely:
  - **Drill:** a phone locked mid backing-track loses no bars and gains none back — the chorus counter is exactly where it was; a Simon chain does not keep sounding into a locked screen; a chord-dictation attempt does not silently close out while hidden; a card's recorded practice time excludes the locked interval.
  - **PDF:** Timed/Loop stops turning pages while hidden and does not fire a queued turn the instant the screen wakes.
  - **Chord Chart:** the metronome and the backing loop go silent while hidden and the chorus/bar counter freezes instead of either racing ahead or rewinding to bar 1 on return.
  - **Lab (trading fours):** the call/answer clock stops while hidden, so a hidden phone is never charged with "did not come in" against bars it never showed, and the app's own call does not keep sounding into a locked phone.
- None of this is a musical claim; nothing here needs an ear, and nothing "unverified as music" applies — the change is interaction/timing correctness, not musical content.
