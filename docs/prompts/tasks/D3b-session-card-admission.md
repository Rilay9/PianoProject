## The goal, in the orchestrator's words

D3a shut every path that asks the gate, and its own probe showed the paths that never ask it: the card takes a rung's list as it stands, so a fresh learner on thirty rungs still gets an unheard groove as the warm-up, the review or the jam. The reviewer's ruling is that an authored placement is not a teaching-use decision and that these rows are automatic offers inside D3a's contract. After D3b one admission — the same reading of the promise fact and the teaching bit the gate uses, exported from `eligibility.ts` and defined nowhere else — is applied wherever the card draws an item from a rung's list without the gate, so a music-promising generated item with no affirmative decision enters no automatic row; a row whose only candidate it was is omitted, or filled by a candidate that already passes; the requirement it served stays unmet, visibly, rather than met by a bypass; the Library and exploration are untouched; and the swap sheet, already gated, is unchanged.

## What is decided

1. **One admission, exported.** `eligibility.ts` exports `admittedForTeaching(item): boolean` (or the builder's name) over the existing `unapprovedMusic`: false only for a generated item whose promise fact is `music` and whose `provenance.review.teaching` is not `true`; true for everything else, runtime drills and notated items included. `eligibleFor` keeps using the same reading; no second definition of the fact or the bit anywhere.
2. **Applied at the one filter the direct paths share.** `session.ts`'s `usable()` — the filter `wantsOf`'s `offer`, `fallbackStep`'s `choose()` and `exposure` already apply — reads the admission, so the `runs`, `done` and `measure` pools, the fallback's `rung` and `prerequisite` steps and the exposure rule refuse an unadmitted item with no change to their own logic. The jam slot, which picks from a lesson's options directly, reads the same admission at its pick. The builder walks every path the reviewer names and any other that draws from a rung's list without the gate (the entry tables them, as D3a tabled the gate's call sites), and where a path does not go through `usable()` it calls the admission — never a parallel test.
3. **A row is omitted, never bypassed.** Where admission leaves a pool empty, the want is not made and the row falls to the next step of the fallback order or is omitted; where a `done` requirement names an unadmitted item, that requirement stays unmet and the rung's row says nothing false. The entry lists, from the merged build, every rung whose requirement or option becomes unfillable until a decision exists, with its rows before and after; no row is kept populated by skipping the admission.
4. **The regressions, red first, per path** (`gateAtTheConsumers.test.ts` or a sibling, on constructed rungs and items): for each of `runs`, `done`, `measure`, the fallback `rung` step, the fallback `prerequisite` step, the jam slot and the exposure rule — an item with `teaching: null` is not offered, one with `teaching: false` is not offered, the same item with `teaching: true` is offered again, and a drill and a notated song on the same list are offered exactly as before; the row omitted or filled by the alternative when the unadmitted item was the only candidate; the swap sheet's cases from D3a unchanged. The card probe from D3a rerun on the built catalogue: the 23 groove rows gone, each row's replacement or omission named.
5. **Record:** `docs/04` (the card's rule: an automatic row is an offer and passes the admission), `docs/08` (the cases), `docs/02` if Part E's sentence on the card needs the clause.
6. **Not D3b's:** any decision on any groove or study; the Library; the swap sheet; Q55's wording; G55, G56 and G60; the rung lists themselves (nothing is removed from a rung; the lists stay authored placement, F's).
