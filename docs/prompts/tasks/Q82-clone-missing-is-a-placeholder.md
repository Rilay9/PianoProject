## The goal, in the orchestrator's words

The fetch step says a source it cannot reach is not a failure, and Mutopia's step keeps that promise: a file that did not arrive is a placeholder with its reason, the curriculum's id resolves, and since Q80 the ladder check reads it as the build's own. The kern and MuseTrainer steps break the promise: a file the clone lacks is dropped, the rungs that name it point at nothing, and validation fails with a score of cross-reference errors and a stale report — a failure that says nothing about the content, on CI and on the Pages deploy, for a GitHub hiccup at clone time. After Q82 the three import steps behave alike: a missing file is a placeholder that says it was not fetched, and whether a build with such placeholders should be deployed stays the reviewer's and the owner's question (Q86), which this seam neither answers nor prejudges.
