## What is decided

1. **The goal.** The reviewer's words: G85's contract "was not only 'show the state'; the Library should also open **the same one project sheet**", through Details, "without spending horizontal row width" (`responses/ba4c6fea.md:22, 34`). Mine: a learner who finds a piece in the Library reaches what they intend to do with it from that piece's own Details, in the words the sheet itself uses, and the row they scanned to find it is exactly as it was.
2. **The door.** Inside `showDetail`, one `listRow` (the shape the sheet already uses for *Play this instead*, :802–809): title `PROJECT_TEXT.door`, *What next with this piece?* — the finish sheet's door to the same sheet (`ScoreScreen.ts:3878`) and G85's builder's recommendation (`entry-147.md:113`); subtitle the sheet's own state line, `projectSince(project.state, project.since, dayKey)` (*Learning since …*) where the index holds a project and `PROJECT_TEXT.none` (*Not a project yet*) where it does not, so the door never implies a project that does not exist; one test hook (an id or `data-` attribute beginning `library-detail-project`). Placed directly above *Open*, with the sheet's actions; *Open* stays last and the only filled box. A placeholder has no *Open*, and there the door, which appears only where a project exists (item 3), goes at the end of the sheet. Tapped, it closes Details (as *Open* and *Play this instead* do) and calls `openProjectSheet({ item, material: materialOfItem(item), bars, owner: section })`. `item` and `material` are the target the index resolved the row with (:1296), so the sheet's own read (`projectSheet.ts:241`, `projectIn` over the same target) finds the same project: the same file under another id, an import by its id. `bars` as Progress computes it (`ProgressScreen.ts:409`). No `onChange`: every sheet write reaches `notify()` (`projectStore.ts:177–190`), and G85's listener (:1309–1321, :1410) already redraws the badge, the filter's result and the count line once per burst; `onChange` as well would draw twice. No new word in `help.ts`.
3. **Where the door appears: the honest-door rule, per item.** The sheet offers from "no project" the four actions of `OFFERS.none` (*Save for later*, *Learn this*, *Prepare it for performance*, *Keep it playable*; `projectStore.ts:69`), under the state line *Not a project yet* and a met line from the encounter history. The door appears where the index holds a project for the item (a project that exists is shown, whatever the item), and, with no project, where the item is projectable **and** opens on the Score screen: `projectOf.has(item.id) || (isProjectable(item) && targetFor(item) === 'score')`. The reasons, each checked at the line:
   - **A bundled song or a MusicXML import** (`targetFor` `score`): honest. The four offers are the learner's statements of intent, allowed before any run by design (`projectStore.ts:62–67`); the met line reads the history the Score screen writes (the only `recordEncounter` calls in `app/src` are `ScoreScreen.ts:3239` and :3245); Progress already sends a learner with no projects to the Library to pick one (`ProgressScreen.ts:447`). An import's project made here is keyed by its id (`none` names no material), and the Score screen finds it by that id when it later loads the bytes (`projectIn`'s id fallback, :125–127).
   - **A PDF import** (`targetFor` `pdf`): no door without a project. `isProjectable` says yes (a PDF's catalogue type is `song`, `entry-147.md:65`), but the PDF viewer writes no encounter, so the sheet would tell a learner who has read that PDF every day *You have never opened it.* (`projectSheet.ts:62`, `PROJECT_TEXT.never`). No door has ever made a project on a PDF.
   - **A placeholder** (*import needed*, `targetFor` `none`): no door without a project. Its identity is `none`, so a project made here is keyed `id:<placeholder id>` (:110–113); the file the learner then imports arrives under its own id (`importIdFor(title, …)`, `importStore.ts:718, 732, 765`), and `projectIn` never takes another id's id-only row (:121–128), so the project would stay on a row that plays nothing. The honest action on that sheet is the import it already offers.
   - **Not projectable** (exercise, drill, excerpt): no door, even where the store holds a row under its id (the index never holds one, :1295).
