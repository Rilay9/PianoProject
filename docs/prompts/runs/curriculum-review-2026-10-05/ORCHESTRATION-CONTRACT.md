# The instructional orchestration contract (the owner, 2026-10-06)

Saved whole as the owner sent it, with the outside reviewer's framing, on 2026-10-06. It is the execution contract for the remaining curriculum work: every learner-facing curriculum brief after the second builder's landing carries its sections (§11 below), the Bizet probe applies it before dispatch (§12), and one bounded reconciliation pass finds where the current ability map misses it (§13). The owner's own words, in the message that carried it: "We want content, generated and found, and we want it correct, accurate, and teaching."

---

We have found a material process miss in the current curriculum remediation.

The restart packet did not ask only for accurate lesson text, correct content placement, CONTROL → MODEL/TRANSFER → MUSIC → INDEPENDENCE station coverage, and honest mode descriptions.

It asked for the app to act as a coherent teaching system:

Learner need → musical requirements → choose best content source → validate for its actual role → present it with the right teaching interaction → measure only what is actually measurable → update the learner model honestly.

And it explicitly gives a legitimate sequence such as:

lesson/demo → controlled exercise → generated sight-read → authentic excerpt → full piece → independent application

The current work has captured content-source choice, station coverage, generator correctness and mode truthfulness fairly well. It has NOT yet made deliberate orchestration of the app's modes, labs, drills, generators, feedback and support fading a mandatory part of each important ability.

Correct that now.

This is NOT permission for another giant research project, another generic mode framework, or another infrastructure project.

## 1. Add one mandatory "instructional orchestration contract" to every important ability

Do this inside the existing ability-map/build-brief process rather than creating a parallel curriculum.

For every MUST ability and every SHOULD ability that receives implementation work, record these fields:

1. Learner deficiency: what can the learner not yet do?
2. Target independent behavior: what should they eventually be able to do without step-by-step prompting?
3. Explanation/demo: what must be explained, shown, heard, counted, named or demonstrated before practice? Which existing app surface does it, if any?
4. CONTROL action: exactly what the learner does; exact exercise/drill/content; why unrelated difficulty has been removed.
5. Tool/mode: exact Score mode, Lab state, drill kind, Chord Chart, Simon, Free Play, etc. Do not merely write "Keep tempo"; say what role it serves.
6. Scaffold supplied. Examples: moving cursor; metronome; app plays the other hand; chord tones lit; bass/drums supplied; notation shown; answer displayed; bar tracker; key named; limited pitch/rhythm vocabulary; fixed fingering/hand position.
7. Feedback: what information does the learner receive after or during the attempt? Pitch error? early/late? missed note? chord membership? scale membership? answer reveal? nothing except their own listening?
8. What is actually recorded/measured: use MODE-SHEET facts, not assumptions.
9. What that evidence cannot prove: state this beside the measured claim. Never let a convenient metric stand in for the target ability.
10. Failure response: if the learner repeatedly fails the same thing, what changes? Examples: slower tempo, smaller range, Loop, one hand, Wait, simpler generated variant, return to explanation/model, reduce simultaneous demands. Do not prescribe arbitrary thresholds without evidence; use existing signals or state that the change is learner-directed.
11. Support fading: which scaffold disappears next? This is mandatory. "Do the same thing three more times" is not support fading.
12. Variation: what changes so the learner cannot succeed purely by memorizing the exact item? Key, register, rhythm, voicing, starting point, accompaniment, phrase, texture, etc., as appropriate.
13. MODEL/TRANSFER: exact real excerpt, simple piece, lead sheet or structured realistic task. What specifically transfers from CONTROL. Do not accept "the target occurs somewhere in the score" as transfer.
14. MUSIC: where the ability contributes to a satisfying musical result.
15. INDEPENDENCE: exact support-free or support-reduced task. Learner must choose/recognize/recover/apply where appropriate, not merely replay the model.
16. Completion/evidence treatment: what can legitimately move rung/skill state? What remains self-checked? What must never produce a green competence claim?

No major ability is "done" merely because its four station cells contain artifacts. The stations must form a defensible learning progression.

## 2. Use MODE-SHEET as a teaching-tool inventory, not just a truth audit

MODE-SHEET already establishes what the tools actually do. Build from it. Use the following default pedagogical roles unless a specific brief gives a better reason.

**Score: Play it to me / Hear it.** Use for: demonstration; hearing the intended result; comparing learner result with a model. Do not use as evidence of learner competence. Remember that hearing an unseen sight-reading item destroys its first-reading status.

**Wait for me.** Use for: first pitch acquisition; unfamiliar notation without time pressure; separating note-finding from timing. Use it deliberately before timed work when note-finding is the problem. Do NOT treat it as rhythm, pulse or fluency evidence.

**Keep tempo.** Use for: integrating correct notes with externally supplied pulse; timing practice; controlled transfer after notes are known. Do NOT call it unaided pulse keeping. The app supplies the clock.

**Loop.** Use for: a bounded trouble spot; repeated transition work; reducing practice-unit size. Do NOT let a looped partial range certify whole-piece ability.

**Duet.** Use for: one-hand acquisition inside musical context; hearing/feeling interaction between hands while isolating one; accompaniment/melody role separation. Do NOT let it certify hands-together independence.

**Rhythm only.** Use for: rhythmic acquisition before pitch is added; contrasting similar rhythmic cells; separating timing from note-finding. This should be used more intentionally where rhythm is the actual new demand.

**Ladder.** Use for: gradually increasing speed after the notes/pattern are stable. It proves an in-session climb, not retention. Pair important speed goals with later cold/retrieval work rather than treating Ladder completion as permanent learning.

**Blind.** Use as: removal of visual score support after material is learned. Do NOT claim the learner has proved memory simply because a Blind run exists: the current record does not preserve that Blind was used. Memory pedagogy must additionally include structure, multiple starts, transitions, cold starts and recovery where appropriate.

**Perform.** Use for: uninterrupted whole-take practice; no-stopping behavior. Do NOT claim it proves recovery strategy, audience readiness or memory landmarks unless those are separately exercised.

**Chord chart.** Use for: playing from harmony rather than full notation; accompaniment; form awareness; progressively taking ownership of voicing/rhythm. Its live chord check is not a full musical judgement. Use support fading: written score → chart → chart with less accompaniment → no chart where appropriate.

**Accompaniment Lab: Read it.** Use for: turning chosen harmony/pattern settings into notation; reading/executing an accompaniment pattern. It tests execution of the generated notation, not choosing a good accompaniment.

**Lab: Bed only.** Use for: free musical practice over a running harmonic/form/time context; improvisation/accompaniment where judgment should stay with the learner. It records essentially nothing useful for competence. That is fine if the lesson says so.

**Lab: Hold the chords.** Use for: highly scaffolded melodic/harmonic exploration over changes. The in-scale count is coarse and unstored. Do not equate it with good improvisation or chord-tone targeting.

**Lab: Play the tune.** Use for: comping beneath an app-supplied melody; testing harmonic choices against melodic context. Chord tones are lit, so use this as a scaffold, not an independence test. A later step should remove that help.

**Trading fours.** Use for: learning to enter/stop in assigned bars; experiencing call/response structure; practicing form under turn-taking. Its current metric cannot tell whether the musical answer actually answers the call. Musical relationship remains self-checked.

**Simon.** Use for: short-term heard-pitch reproduction; gradually increasing auditory sequence length. Do not call it pitch naming, interval recognition, long-term memory or pure ear evidence when visual key help is available and not recorded. If an ability needs genuine ear-only behavior, remove visual help in the teaching design and do not claim stored evidence can distinguish it unless the app records that state.

**Ear/theory drills.** Be exact about whether the drill asks the learner to: recognize/name; reproduce; construct from a symbol; tap something written. Several existing drills measure reproduction while old lesson wording claimed recognition. Preserve the corrections already made. When the target is recognition or naming and the app only verifies production, make naming an explicit learner action before playing, and label it self-checked unless/until a real recognition interaction exists.

**Free Play.** Use for: experimentation; discovery; trying voicings/shapes; composition/improvisation sketches. It is not an assessment mode.

**Paper / external recording / self-check.** Use them when they are genuinely the best teaching interaction. Do not contort MIDI into pretending it can assess: singing; written transcription; style quality; phrasing quality; composition quality; listening/revision; physical relaxation; ensemble listening.

## 3. Require support-fading sequences, not mode mentions

For every important ability ask: what help is present on attempt 1 that is gone by the final task?

Examples of legitimate fades: Listen → Wait → Keep tempo. Both-hands notation → Duet/one hand → both hands. Rhythm only → rhythm + pitches. Full notation → lead sheet/chord chart → no chart. App-supplied bass → learner supplies bass. App-supplied melody → learner supplies melody. Chord tones lit → no chord-tone display. Fixed key → several keys → learner chooses/handles requested key. One four-bar section → full form. Loop → whole take. click + tracker → tracker only → neither. seen/rehearsed → cold start. starting at beginning → structural restart points. exact generated example → varied generated examples → real excerpt. given pattern → identify/select pattern independently.

If a row has no support fade because none is appropriate, say why.

## 4. Make failure remediation part of the teaching design

The packet explicitly calls for changing strategy after repeated unchanged failure. Do not create a generic adaptive engine first. For each implemented ability, identify the useful existing fallback path.

- Note-learning failure (Keep tempo fails repeatedly): slow down; smaller Loop; Wait; separate hand; return to model/explanation.
- Rhythm failure (pitch and rhythm together fail): Rhythm only; count/tap; generated simpler rhythmic control; restore pitches.
- Hands-together failure: Duet or isolated hand; practice transition/figure; restore both hands.
- Accompaniment failure: Read it / supplied pattern; Play the tune with melody supplied; Chord chart; learner chooses pattern; remove chart.
- Improvisation overload: restrict pitch material; shorter response; fixed bars; app-supplied harmony/bass; gradually restore freedom.
- Memory failure: inspect form; landmark start; transition Loop; cold restart; whole Perform pass.

Do not merely lower tempo forever if the actual failure is conceptual, rhythmic, memory-related or coordinative.

## 5. Generators must exploit controlled variation

Retain the existing generator ruling: real inspected music for MODEL/TRANSFER; generation for CONTROL/isolation; generated mini-piece only when real material/templates cannot serve. But make generator pedagogy explicit. A generator is valuable because it can control one dimension at a time.

For a generated CONTROL family, the build brief must name: what is fixed; what varies; why that variable changes now; what demand is deliberately absent; what near-miss/contrast is pedagogically useful; when the learner stops using generated material and moves into real music.

Preferred pattern: canonical example → controlled variation → contrast/near-miss → new key/register/context → authentic transfer. Not: 30 random seeds → complete 3 → row done.

**Sight-reading.** Treat this separately because unseen material is intrinsic to the skill. Progress deliberately through: note range; directional/interval reading; position changes; key; metre; rhythm; compound metre; leaps; texture/polyphony; articulation; accidentals; density; length. Do not let hard repertoire replace continuing unseen reading.

**Named style generators.** Keep: published/sourced definition → exact family contract → generated control → independent structural checker → contrast near-miss → real model/transfer. Examples already in scope: habanera versus tresillo; bossa basic pattern versus quarter-only/tresillo/habanera near-misses; arpeggiated guajeo versus block-chord/ponchando; future walking bass/boogie/stride/etc. only where an authorised learner chain needs them. No title/metadata-based style generation.

## 6. Keep three different kinds of verification separate

This distinction is mandatory.

A. **Content verifier.** Does the exercise/file actually contain what we claim to teach? Examples: onset mask; durations; pitch roles; metre; interval spelling; chord progression; range; hand/staff; near-miss fails. This protects curriculum truth.

B. **Performance measurement.** What did the learner execute during this interaction? Examples: pitches; timing against supplied clock; missed/wrong notes; hand played; run range; chord/scale membership where the relevant tool actually computes it.

C. **Learning/transfer assessment.** Can the learner recognize, choose, adapt, recover and use the ability with reduced support?

Do NOT let A or B stand in for C. A green generator checker proves the content. A green Keep-tempo run proves one execution under that support. Neither proves independent musical ability. Where C cannot be objectively measured, design an honest task and say it is self-checked.

## 7. Retrofit the major cross-track strands explicitly

The packet calls these out. Do not merely verify their existence.

- **Sight-reading.** Teaching chain: unseen item → appropriate minimal guidance → Keep tempo first-read evidence → diagnose demand → targeted practice after first-read status is spent → next unseen item. Never Hear the phrase before first-read evidence.
- **Transposition.** Build progression across the curriculum: tiny pattern/melody → I-IV-V → chord progression → accompaniment pattern → chart/song → singer/practical key → blues/jazz/improv use. Use Lab key changes, generated controls and real charts where they fit. Do not leave transposition in one theory rung.
- **Memory.** Use: form/landmarks → sections/transitions → multiple start points → Blind/no score → cold starts → interruption/recovery → Perform. Blind alone is not memory pedagogy.
- **Ear.** Include production: hear → sing/name/clap where relevant → play back → transcribe/write where relevant → find bass/root → apply to real song. Do not reduce ear training to selecting or reproducing synthetic prompts.
- **Score study.** Before intermediate/advanced pieces require an explicit pre-play scan where relevant: key; metre; form; repeats; recurring figures; accompaniment texture; cadences; transition/hot spots; intended practice units. Then use Loop/sections based on that analysis rather than arbitrary bar chopping.
- **Performance/recovery.** Use: cold start → whole no-stopping take → record/listen → structural restart points → deliberate recovery after interruption/error → later performance simulation. Do not turn Perform mode alone into the whole strand.

## 8. Apply this concretely to style and accompaniment tracks

**Blues.** Use the existing blues-own-left-hand ladder as the exemplar. CONTROL: written authored shuffle, LH measured, then both hands. MODEL: real Morton/Pinetop material where admitted. TRANSFER: short RH fragments while learner supplies LH. MUSIC: whole chorus. INDEPENDENCE: learner chooses key/LH figure, no tracker/click/chart, records and listens. This is approximately the instructional depth other important abilities should reach.

**Habanera/tresillo.** Do NOT make this merely: generated exercise → Bizet Keep tempo → row done. Desired teaching progression: (1) explain/name the two cells; (2) Hear/demo them; (3) tap/play in Rhythm only; (4) side-by-side generated CONTROL where only the cell differs; (5) Keep tempo on generated LH; (6) vary key after rhythmic identity is stable; (7) see/hear Bizet in musical context; (8) play the selected Bizet LH model; (9) contrast with real tresillo material such as The Crave; (10) identify which cell a new passage uses; (11) later use/recognize the cell without the lesson naming it first. The exact interaction can change during the build, but the support progression must exist.

**Bossa.** Do not stop at generating the sourced root/fifth cell correctly. Sequence: Hear/model basic pattern → controlled LH pattern → add harmony → change keys/progression → apply beneath real melody/lead sheet → remove pattern prescription and ask learner to choose/use it. Use Lab/Chord Chart where they genuinely reduce one demand at a time.

**Guajeo / ponchando.** Teach the contrast: source-defined arpeggiated guajeo CONTROL versus block-chord sibling near-miss; then real block-chord material such as La Negra as contrast/MODEL; then application where learner chooses the appropriate texture. Do not make the checker the lesson.

**Minor ii-V-i / jazz.** A sensible chain should include: construct/hear shells → generated/chord drill CONTROL → Lab in several keys → Blue Bossa real MODEL → play/voice from its symbols → apply to another standard → choose guide tones/voicing independently. Do not count "Blue Bossa contains ii-V-i" as teaching completion.

**Pop accompaniment.** Use: specific accompaniment pattern CONTROL → Lab Read it → Lab Play the tune → familiar written example → lead sheet/Chord Chart → learner-built arrangement. The Vienna lead-sheet/full-arrangement pair is an especially good build first, compare afterward task.

**Rock/metal reduction.** Do not require piano notation to contain the target guitar/bass texture literally. Use real ensemble source → inspect/transcribe/reduce → choose what piano keeps/drops → test register/density → build section arrangement → whole-song project.

**Hymns/gospel.** Use modes according to role: voice-leading/control → Duet/part isolation → full texture → accompaniment under melody → chart/harmony work → reharmonization/live adaptation only after prerequisites.

**Jam / ensemble.** Use Bed only / Chord Chart / Trading fours for their distinct functions. Explicitly teach: form; entry; stop; listening during the other person's turn; shared endings; recovery. Do not call in-scale-note count "jamming ability."

## 9. Familiar repertoire is not filler

Stand By Me, Your Song, Someone Like You and later familiar finds should enter only where they improve this chain. Examples: Stand By Me, familiar accompaniment TRANSFER / arrangement independence; Your Song, accessible full musical integration; Someone Like You, later persistent arpeggiated accompaniment transfer; Vienna lead sheet + full arrangement, build your own accompaniment first, then compare with an authored realization; Country Roads separated parts, reduction/arrangement exercise. They may also stay optional/fun if no station needs them. Familiarity is pedagogically useful for internal timing, ear checking, anticipation and motivation, but does not by itself justify a required placement.

Use existing machinery first. If a concrete learner chain exposes a missing product capability, record: learner need → current tool limitation → smallest capability needed → concrete consumers. Then build it only if the gain is real.
