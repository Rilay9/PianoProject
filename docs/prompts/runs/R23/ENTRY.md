## Judgement

**Branch 3b: the model gap is returned. The validator's song criterion, `ladder_report.py`, `thinLessons` and `docs/02-curriculum.md`:74 are untouched.** The read-only report is `application-report.md`, generated by `scripts-application-report.py` from this build (`build.py --offline` at `7d9de990`, the owner's default personal build). It checks the four facts the required change names, one by one.

1. **The target claim does not exist anywhere.** The `runs` requirement carries `from`, `items`, `count`, `performance` and `accuracy`, and no target (`app/src/curriculum/types.ts` `RunsRequirement`). The lesson JSON has no such field either: the keys over all 109 lessons were read, and `finder.skill` is search prose, which no measurement reads. `claims.rung_claims_of` returns every measurable claim a rung makes and marks none of them as the application's. `rung-claims.md`, `excerpts.candidate_rungs` and `study.candidate_rungs` all test "establishes at least one of the rung's claims", which is the proxy `responses/71730e65.md` refuses. At runtime the session asks the gate about a song-run option as `{ for: 'equivalent' }`, "an automatic experience claiming no opportunity" (`eligibility.automaticFromList`, reached from `session.wantsOf`:906 through `fromList`). It then offers the first passing option in the rung's authored order (`session.pick`:409–411: `seed % offer.length`, and the seed stays 0 until the learner shuffles). `candidates.MaterialRequirements.target` has room for a target, but its only constructor is `requirementsFromWant`, and a song run's want is `equivalent`.
2. **Measured opportunity exists twice and is joined to nothing.** `claims.status_of` (build) and `eligibilityCore.opportunity` (runtime) read the same fields by the same rule. That was established by comparing the code. No test holds the two equal across the catalogue; one paired case exists (`test_taught_at.py`:540–567 with `copingQuestion.test.ts`). Whether they stay one computation is a question for CL11, not this lane.
3. **Teaching-use admission exists only in the app** (`admittedForTeaching` / `unapprovedMusic`). The build carries its inputs, but no Python reader combines them into a verdict. **On this build the admission applies to none of the 345 song listings.** None of them is generated music or an excerpt, and those are the only two kinds the admission refuses. This was read with the app's own functions through a probe, not with a Python twin.
4. **Runtime, creative or ear options among the song listings: 0.** `status_of` reports such an option as `runtime` / `the reader's`, so it neither passes nor fails, and that convention is adequate. The decision's creative, harmony, accompaniment and ear applications sit today on the 43 `songOptional` rungs. Those rungs ask for exercises, so no song count reads them.

No function joins (1) with (2) and (3) for a rung's application, at build time or at runtime. The stop condition holds.

**The holistic finding: the gap is larger than "compose what exists".** All 61 rungs that ask for a song run name at least one concept no detector measures. 41 of them name nothing measurable at all: the target concepts are things like phrasing, voicing, pedalling, chord symbols, four-part harmony and rubato. So even with a target named per rung, most rungs would get the honest answer *unknown*: the notes cannot establish the opportunity, and the only other source is a person's teaching-use review (0 on any rung option, per the build's own warning). A build-failing gate cannot hold *unknown* without either passing or failing it falsely, which is exactly what the required change forbids.

The brief's shape fits this stop: report first, stop if nothing composes. But the "small design decision" the required change expects is really three decisions:
- (i) where a rung's application target is written in the curriculum's data;
- (ii) what the build enforces at a rung whose target no detector measures. That is most rungs. One option is that the gate stays a count or a non-empty check and strength is reported rather than gated; that is a suggestion, not decided;
- (iii) whether the session asks that target of the song it offers. Today the authored order stands in for fit, so a weak option listed first is offered first. The decision's own worry, "fed three mediocre choices", reaches the learner through `session.pick` as well as through the validator.
