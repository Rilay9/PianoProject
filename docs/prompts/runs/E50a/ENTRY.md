## Deviations, with reasons

- **The window became a committed, generated table**, on the reviewer's rule relayed mid-lane. I had built, tested and mutated the build-day-plus-14 constant, then replaced it. Every case that read it was rewritten and re-run: the Python unit class, the build's field test, item 5's third check and the mutants (`mutants.txt`'s history).
- **Former identities are a lookup, not a date sweep.** `convert.former_identities` reads `tools/content/former_identities.json` and re-proves each entry against the built file.
- **The table sits outside the tool fingerprint**, on purpose: it changes provenance, never a converted file.
- **No cache.** A warm build re-proves every entry, one zip per recorded entry of a row.
- **`test_measured_truth.py` gained two cases, not one.** One checks that no file the converter wrote carries a date. The other checks that `formerIdentities` equals the table's entries for the file's undated form.
- **The before build's identities equal the laptop's 22:28 catalogue for all 211 build-converted files** (`historical-dates.txt`). So the item 6 comparison stands for the laptop as it was at dispatch.
