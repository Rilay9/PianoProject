## The identity table: what each source's `material` is, and how equality is decided

| Source of the run | `material` | Written by | Equal when (`material.sameMaterial`) |
| --- | --- | --- | --- |
| A generated catalogue item (scales, studies, grooves, the pentatonic items) | `{kind: 'generator', family, version, seed, recipe, tempoBpm}` — the build's `provenance.identity` (`review.current_identity`: `drill.generator`, `drill.params` with the hands, `tempoBpm`) | `build.attach_provenance`; the run copies it (`material.runFacts`) | family, version, seed, recipe (deep, key order free) and tempo all equal — D2's `sameIdentity` |
| A notated item (PDMX, kern, MuseTrainer, authored) | `{kind: 'file', sha256}` of the built file | the build | the sha256 |
| An excerpt | `{kind: 'file', sha256}` of the **cut**, never the parent — E1's field, generalised, not renamed | the build (E1's Score screen hashed the loaded bytes; the build hashes the same file, and the app no longer recomputes it) | the sha256 |
| A sight-reading phrase (runtime) | `{kind: 'generator', family: 'sight-reading', version, seed, recipe, tempoBpm}`: the phrase's `generator` (D1a), **the generator options it was written from** — the row's params with the reader's moves and the rung's hold (`readingOptions`) — seed and version apart, and the tempo written into it | the Score screen (`material.phraseMaterial`) | as a generator: reopening the same version, seed and recipe is equal; another seed, version, move or hold is not (`materialIdentity.test.ts`) |
| A drill made when it opens (the drill screen's runs) | `{kind: 'none', why: 'made when it opens: no file the build keys'}` | the drill screen (`runFacts`) | never — contact by id alone |
| An import | `{kind: 'none', why: 'an imported score: no build identity'}` | the Score screen | never — by id alone |
| A placeholder | `none` (`no notation is bundled`) on the row; never played | — | never |
| A legacy run (before D4), a paper run | absent | — | by id alone: `met-by-id` |

**The deviation, and why.** The brief and the reviewer name "the exact `ReadingRecipe`" as the phrase's recipe. The `ReadingRecipe` (`{row, moved, easy}`) does not determine the phrase: the row's params and the judging rung's hold also do — which is why `evidenceJob.candidatePhrases` has to try three option sets to write a stored run's phrase again. So the recipe is the options the phrase was written from, which is exactly what D2's identity holds for a generated catalogue item (`drill.params`: the generator's input). The row id and `easy` are left out on purpose: two rows whose options are equal write the same phrase from the same seed, and calling those two materials would be a false first contact. **Tempo stays in D2's type**: it is the options' `bpm` or the version's default, so it is determined by the recipe and adds no discrimination; no second identity structure exists (`Identity` is `review/record.ts`'s, reused by `types.ts` through `import type`).
